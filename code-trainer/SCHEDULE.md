# 按表操課日程表

> **前提假設：每週約 10 小時。** 時數不同請看最後的[換算表](#時數換算)。
> 這份表定義在 `plan.json`，可以自己改。

**每天只要打一個指令：**

```bash
python trainer.py today
```

它會告訴你今天是第幾週、屬於哪個階段、今天該做什麼、有沒有到期複習、本階段進度到哪。

第一次使用先設定開始日：

```bash
python trainer.py plan --start today     # 或 --start 2026-08-10
python trainer.py plan                   # 看完整階段路線與進度
```

## 每週節奏

| 日 | 內容 | 時間 | 具體做什麼 |
|---|---|---|---|
| **週一** | 程式軌新題 | 75 分 | `sync` → `review` → `next` → 解題 |
| **週二** | 數學軌新題 | 75 分 | `next --track math` → 解題 |
| **週三** | 程式軌新題 | 75 分 | 解題 + 看標準解 |
| **週四** | 複習 + 課程 | 75 分 | `review` 到期題 → 課程影片 40 分鐘 |
| **週五** | 程式軌新題 | 75 分 | 解題 + 請 AI 教練 review 你的 code |
| **週六** | 課程 + 數學軌 | 150 分 | 課程 90 分鐘 → 數學軌一題 |
| **週日** | 休息／補進度 | — | 落後就補；沒落後就真的休息，跑 `status` 看一週成果 |

**約 5 題／週。** 程式軌 3 題、數學軌 2 題，另外一天專門複習。

### 幾條不要打破的規則

1. **複習永遠優先於新題。** 到期沒複習就往前衝，等於在漏水的桶子裡加水。
2. **週日真的要休息。** 排了 6 天已經很滿，第 7 天硬撐只會讓你第 3 週就放棄。
3. **一天只做一題。** 做完一題把標準解讀完、把 review 聽完，比連做三題有用得多。
4. **卡住超過 45 分鐘就按 hint。** 但按之前先把你的想法寫下來（見 README 的提示策略）。
5. **每次練完 `sync`。** 一秒鐘的事，換來的是換電腦不用重來。

## 階段路線圖

任何說「6 個月從新手到 CV 研究者」的計畫都在騙你。

但**你不需要走完才有用**：P3 結束（約 9 個月）你就能讀懂大部分 CV 論文的實作，
P5 結束（約 14 個月）你就具備做 SLAM 研究的數學與工程能力。

## 時數換算

| 每週時數 | 節奏 | 總長 | 適合 |
|---|---|---|---|
| **6 小時** | 平日 3 天 + 週六，約 3 題/週 | 約 150 週（35 個月） | 研究/課業很滿的學期 |
| **10 小時** | 平日 5 天 + 週六，約 5 題/週 | **88 週（20 個月）** | **基準** |
| **16 小時** | 平日 5 天各 2 小時 + 週末，約 8 題/週 | 約 57 週（13 個月） | 暑假、寫論文前的衝刺期 |

```bash
python trainer.py plan --start today --hours 16
```

**不建議超過每週 16 小時。** 這條路線的瓶頸不是時間，是**消化**——
SVD、反向傳播、李代數這些東西需要睡覺的時候讓大腦處理，硬塞沒有用。

## 落後了怎麼辦

會落後的，這很正常。按優先序處理：

1. **先砍課程，不要砍題目。** 課程可以之後補、可以加速看，
   但「動手寫過」是不能加速的。
2. **再砍程式軌的節點數，不要砍數學軌。** 程式軌後面的節點（S3 競賽、S4 部分）
   對研究不是必要的；數學軌每一節都會被後面用到。
3. **最後才延長階段時間。** 直接接受這個階段多花 2 週，比草草帶過好。

**絕對不要做的事：跳過複習去趕新題。** 那會讓你前面做的全部白費。

如果連續兩週都嚴重落後，就把 `--hours` 調低重設日程：

```bash
python trainer.py plan --start today --hours 6
```

誠實的慢，好過假裝的快。

## 每月回顧（每 4 週做一次，15 分鐘）

```bash
python trainer.py status        # 兩軌完成度、連續天數
python trainer.py log -n 60     # 這個月做了什麼
python trainer.py plan          # 階段進度與里程碑
```

問自己四個問題：

1. 這個月的**里程碑**達成了嗎？沒有的話，是哪一節卡住？
2. 哪些節點的**提示用量**特別高？（`status` 會列出來）那是要回頭補的地方。
3. 有沒有**跳過複習**？跳過幾次？
4. 現在的**時數設定**還符合現實嗎？不符合就改，不要每週都在內疚。
