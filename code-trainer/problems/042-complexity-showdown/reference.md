# 042-complexity-showdown · 同一件事的四種寫法 — 參考解

## 標準解

```python
def common_labels(a, b):
    bset = set(b)          # O(len(b)) 一次，換來之後每次查詢 O(1)
    seen = set()
    out = []
    for x in a:
        if x in bset and x not in seen:
            out.append(x)
            seen.add(x)
    return out
```

時間 **O(len(a) + len(b))**，空間 O(len(a) + len(b))。

## 四種寫法的實測

同樣是 10 萬 × 10 萬：

| 寫法 | 複雜度 | 10⁵ 規模 |
|---|---|---|
| `[x for x in a if x in b]` + 去重 | **O(n²)** | 幾十分鐘 |
| 排序 b 再 `bisect` | O(n log n) | ~0.3 秒 |
| **轉 set 再查**（標準解） | **O(n)** | ~0.03 秒 |
| `list(set(a) & set(b))` | O(n) | ~0.02 秒，但**順序錯** |

**最後一個是這題的陷阱**：它更快、更短，但 `set` 不保證順序，
所以結果每次執行可能不同。測資 `["z","y","x"]` 配 `["x","y","z"]` 專門抓它。

> **不要為了短而放棄規格。** 「順序依 a」是需求的一部分。

## 為什麼 set 的 `in` 是 O(1)

`set` 底下是**雜湊表**：

```
"cat"  →  hash("cat")  →  某個桶的編號  →  直接跳過去看
```

不用比較其他元素，**一步到位**。代價是：

1. 元素必須可 hash（不可變）——這就是 041 那題 `box` 要轉 tuple 的原因
2. 多用一份記憶體
3. 不保證順序

`list` 的 `in` 只能從頭比到尾，**因為它對內容一無所知**。

## 「用 O(n) 前處理換掉 O(n²) 查詢」

這是演算法設計最常見的一招，值得記住它的形狀：

```
原本：對每個 x，掃一遍 b          → n × n
改成：先掃一遍 b 建索引，再對每個 x 查一次 → n + n
```

**前處理的成本被攤平了。** 你在 004-top-k-words（dict 計數）、
019-dedupe-keep-order（set 記錄看過的）、041（set 去重）都用過同一招。

2.2「雜湊表」整節就在練這個模式的各種變形（分組、前綴和 + 雜湊、兩數之和）。

## 複雜度直覺：什麼規模對應什麼複雜度

節點 1.9 的核心是**看到輸入規模就知道能用什麼演算法**。粗略的換算（Python，一秒內）：

| n | 可以接受的複雜度 |
|---|---|
| 10⁶ 以上 | O(n)、O(n log n) |
| 10⁵ | O(n log n) 沒問題，O(n²) 不行 |
| 10⁴ | O(n²) 勉強（10⁸ 次操作，Python 約幾十秒——通常還是太慢） |
| 10³ | O(n²) 可以，O(n³) 勉強 |
| 20 以下 | O(2ⁿ) 甚至 O(n!) 都行 |

**Python 大約每秒 10⁷ 次基本操作**（C++ 是 10⁸–10⁹）。
看到題目說「最多 10⁵ 個元素」，就該立刻排除 O(n²)。

這個直覺在 S3 競賽題是必備的——那裡的時限通常是 1 秒，
而題目給的 n 就是在告訴你「該用什麼複雜度」。

## 常見錯誤

1. **忘記轉 set** —— 小測資全過，大測資跑到天荒地老。
2. **`set(a) & set(b)`** —— 順序不確定。測資 6 抓。
3. **在迴圈裡重複建 set** —— `for x in a: if x in set(b)` 每圈都重建一次，比原本更慢。**前處理要在迴圈外面。**
4. **忘記去重** —— `["x","x","x"]` 會輸出三個。
5. **用 `sorted()` 排序輸出** —— 題目要 a 的順序。
6. **`out` 用 `in` 檢查去重**（`if x not in out`）—— out 是 list，又變回 O(n²)。要另外用 set。

## 延伸

這題只有一個技巧，但它的變形佔了 LeetCode 的一大塊：

| 題型 | 用什麼當索引 |
|---|---|
| 兩數之和 | dict：值 → 索引 |
| 分組 anagram | dict：排序後的字串 → 清單 |
| 最長無重複子字串 | set/dict：字元 → 上次出現位置 |
| 子陣列和為 k | dict：前綴和 → 出現次數 |

**共同點：花 O(n) 建一個「查得快」的結構，把巢狀迴圈砍成單層。**
