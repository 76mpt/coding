# 059-zero-drift-segments · 淨位移剛好是 k 的片段

- 階段：資料結構與演算法（LeetCode 風格） / 2.2 雜湊表
- 語言：Python　難度：standard　互動方式：實作函式
- 要實作的入口：`count_segments`
- 提示：共 4 階（`python trainer.py hint 059-zero-drift-segments`）
- 測資：12 筆（`python trainer.py test 059-zero-drift-segments`）

────────────────────────────────────────────────────────────────────

里程計每一幀回報一個**位移增量** `deltas[i]`：整數，單位公釐，沿著走廊的方向，
**可正可負**——機器人會前進也會倒退。

你想找出所有**淨位移剛好是 `k`** 的連續片段。
`k = 0` 特別有用：淨位移為 0 代表機器人**回到了片段起點**，那是迴環偵測的候選。

實作 `count_segments(deltas, k)`，回傳這種連續片段的**個數**。

**範例**

```python
count_segments([1, 1, 1], 2)                  ->  2     # 位置 0-1 和 1-2 的 [1, 1]
count_segments([1, -1, 0], 0)                 ->  3     # [1, -1]、[0]、[1, -1, 0]
count_segments([3, 4, 7, 2, -3, 1, 4, 2], 7)  ->  4     # [3, 4]、[7]、[7, 2, -3, 1]、[1, 4, 2]
count_segments([0, 0, 0], 0)                  ->  6     # 每一段都是 0：長度 1 有 3 段、2 有 2 段、3 有 1 段
```

第一個範例：兩個 `[1, 1]` 內容一樣，但**位置不同就分開算**。

**限制**
- `0 <= n <= 2 * 10^5`
- `-10^4 <= deltas[i] <= 10^4`，`-10^9 <= k <= 10^9`
- 片段至少要有一個元素（空片段不算）
- 答案可能很大（全是 0 的時候是 n(n+1)/2），Python 的 int 不會溢位

**效能要求**：大測資 n = 200,000 並有時間上限。
枚舉所有 (起點, 終點) 是 O(n²) ≈ 2×10^10 次運算，必然超時。

054 你用滑動視窗在 O(n) 解掉了「和 ≥ target 的最短區間」。**這題不能用滑動視窗**——
那題成立的前提是元素非負，所以「右界往右擴，區間和只會變大」。
這題有負數，這句話不成立了。你需要另一個工具，而它會用到 056 剛練過的東西。
