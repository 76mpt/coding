# 072-search-bounds · 排序陣列的上下界查詢

- 階段：資料結構與演算法（LeetCode 風格） / 2.5 二分搜尋
- 語言：Python　難度：warmup　互動方式：實作函式
- 要實作的入口：`search_bounds`
- 提示：共 4 階（`python trainer.py hint 072-search-bounds`）
- 測資：10 筆（`python trainer.py test 072-search-bounds`）

────────────────────────────────────────────────────────────────────

排序過的資料是整個 2.5 節的前提。這一節開頭先把最基本的那兩個查詢寫熟，
因為後面每一題（包括「二分答案」）都是它們的變形。

`nums` 是一個**非遞減**排序的整數陣列（可以有重複值）。
對每個查詢值 `t`，你要回答兩個索引：

```
lower = 最小的 i 使得 nums[i] >= t      （沒有這樣的 i 就回傳 len(nums)）
upper = 最小的 i 使得 nums[i]  > t      （沒有這樣的 i 就回傳 len(nums)）
```

這兩個數就是 `t` 在陣列裡「該插進去的位置」的左右邊界。
它們的差 `upper - lower` 剛好是 `t` 出現的次數——
`t` 根本不存在時兩者相等，差是 0。

實作 `search_bounds(nums, targets)`，回傳一個 list，
第 k 個元素是 `[lower, upper]`（對應 `targets[k]`）。

**範例**

```python
search_bounds([1, 2, 2, 2, 3, 5], [2])
# -> [[1, 4]]            2 從索引 1 開始、到索引 4 之前，出現 3 次

search_bounds([1, 2, 2, 2, 3, 5], [0, 1, 3, 4, 6])
# -> [[0, 0],            0 比所有元素小 → 兩個都是 0，出現 0 次
#     [0, 1],            1 在索引 0，出現 1 次
#     [4, 5],            3 在索引 4
#     [5, 5],            4 不存在，但該插在索引 5
#     [6, 6]]            6 比所有元素大 → 兩個都是 len(nums)

search_bounds([], [1, 2])
# -> [[0, 0], [0, 0]]
```

注意第四個查詢：`4` 不在陣列裡，`lower` 和 `upper` 仍然相等，
而且都指向「如果要插入 4，它該放的位置」。
**不存在的值也有明確答案**，這是 lower/upper bound 比「找到就回傳索引、找不到回傳 −1」有用的地方。

## 兩個函式只差一個等號

把兩者寫出來之後對照一下，你會發現它們的差別只有比較運算子裡的那個 `=`。
這不是巧合：`lower` 在問「第一個**不小於** t 的位置」，
`upper` 在問「第一個**大於** t 的位置」，
兩個都是「第一個滿足某個條件的位置」——而那個條件在陣列上是**單調**的
（前面一路不滿足，後面一路滿足）。

二分搜尋真正在做的事就是這個：**在一個布林值由 False 變 True 的陣列上，找那個分界點**。
看懂這件事，007 那種「二分答案」的題目就不再是另一個技巧，而是同一件事換個外衣。

**限制**
- `0 <= len(nums) <= 2 * 10^5`，`0 <= len(targets) <= 2 * 10^5`
- 元素是整數，可能有負數與大量重複值
- `nums` 保證已經非遞減排序
- **不要用 `bisect` 模組**。那個模組做的就是這題，手寫一次是這題的全部目的
- 大測資有 20 萬個元素、2 萬個查詢並有時間上限。
  每個查詢都線性掃一遍是 `O(n·q) = 4×10^9`，必然超時
