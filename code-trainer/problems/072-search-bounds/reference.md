# 072-search-bounds · 排序陣列的上下界查詢 — 參考解

## 標準解

```python
def search_bounds(nums, targets):
    n = len(nums)

    def lower(t):
        lo, hi = 0, n                  # 不變量：答案一定在 [lo, hi) 裡
        while lo < hi:
            mid = (lo + hi) // 2
            if nums[mid] < t:          # mid 還不滿足「>= t」→ 答案在右邊
                lo = mid + 1
            else:                      # mid 滿足了 → 答案可能就是 mid
                hi = mid
        return lo

    def upper(t):
        lo, hi = 0, n
        while lo < hi:
            mid = (lo + hi) // 2
            if nums[mid] <= t:         # 只差這一個等號
                lo = mid + 1
            else:
                hi = mid
        return lo

    return [[lower(t), upper(t)] for t in targets]
```

## 為什麼這個寫法不會錯

這一段值得讀慢一點，因為它是**所有**二分搜尋題的通用模板，不只這一題。

把陣列上的條件寫成 `P(i)`（`lower` 的條件是 `P(i) = (nums[i] >= t)`）。
前提是 `P` **單調**：一旦某個位置成立，它右邊全部成立。
我們要找第一個成立的位置，全都不成立就回傳 `n`。

**不變量**：答案永遠落在閉區間 `[lo, hi]` 裡。

- **初始成立**：`lo = 0`、`hi = n`。答案最小是 0、最大是 `n`（代表全不成立），
  所以確實在 `[0, n]` 裡
- **每輪維持**：`lo < hi` 時 `mid = (lo + hi) // 2` 必然滿足 `lo <= mid < hi`。
  - `P(mid)` 為假 → 由單調性，`mid` 左邊也全為假 → 答案 `> mid` → 新區間 `[mid+1, hi]` ✓
  - `P(mid)` 為真 → 答案是「第一個」為真的位置，所以答案 `<= mid` → 新區間 `[lo, mid]` ✓
- **終止時**：`lo == hi`，閉區間只剩一個數，而答案在裡面 → 答案就是 `lo`

**終止性**：假的那一支 `lo` 變成 `mid + 1 >= lo + 1`（嚴格變大），
真的那一支 `hi` 變成 `mid <= hi - 1`（嚴格變小）。
區間長度 `hi - lo` 每輪至少少 1，所以一定會停。

這也解釋了為什麼兩支**不能都寫 `mid`**：
如果假的那一支寫 `lo = mid`，當 `hi = lo + 1` 時 `mid == lo`，`lo` 沒變、`hi` 沒變 → 無窮迴圈。
那個 `+1` 不是經驗法則，是終止性的來源。

## 一個好用的等價關係

對**整數**陣列：

```python
upper_bound(t) == lower_bound(t + 1)
```

因為「第一個 > t」和「第一個 >= t+1」在整數上是同一件事。
所以你其實只要寫一個 `lower`，`upper(t)` 直接呼叫 `lower(t + 1)`：

```python
return [[lower(t), lower(t + 1)] for t in targets]
```

程式少一半。但**浮點數不適用**（`t + 1` 跳太遠），而且面試時兩個都要寫得出來。
知道這個關係的價值是：它告訴你 `lower` 是更基本的那一個，`upper` 只是它的特例。

## 複雜度

- 時間 **O(n_q · log n)**：每個查詢 `log₂(2×10⁵) ≈ 18` 次迴圈，2 萬個查詢約 36 萬次
- 空間 **O(n_q)**：只有輸出。搜尋本身是 O(1)

線性掃描是 `O(n · n_q) = 2×10⁵ × 2×10⁴ = 4×10⁹`，差了四個數量級。

## 常見錯誤

1. **無窮迴圈** — 兩個分支都寫 `hi = mid` / `lo = mid`，區間不變小。
   這是二分第一名的 bug，而且在 `n = 2` 這種小輸入上就會卡死。
2. **`hi = n - 1` 配閉區間，然後忘了 `n = 0`** — `hi = -1`，迴圈條件 `lo <= hi` 直接不成立，
   回傳 0 碰巧對；但 `t` 比所有元素大時回傳 `n - 1` 而不是 `n`，錯。
   空陣列那筆和 `[1,2,2,2,3,5]` 配 `t = 6` 那筆會抓到。
3. **找到就回傳** — 寫成 `if nums[mid] == t: return mid`。
   有重複值時你回傳的是**隨便一個** `t` 的位置，不是第一個。
   `[1,2,2,2,3,5]` 配 `t = 2` 可能得到 2 或 3 而不是 1。
   這題的重點就是「第一個」，所以不能提早回傳。
4. **`lower` 和 `upper` 的等號放錯** — 兩個都寫 `<` 或都寫 `<=`，於是兩個函式回傳一樣的值。
   `[7,7,7,7]` 配 `t = 7` 立刻現形：你會拿到 `[0, 0]` 或 `[4, 4]` 而不是 `[0, 4]`。
5. **用了 `bisect`** — 會過測資，但這題就沒意義了。
   順帶一提，`bisect.bisect_left` / `bisect_right` 就是這題的 `lower` / `upper`，
   名字不同而已；之後實務上當然要用它。
6. **（C++ 時要注意）`mid = (lo + hi) / 2` 溢位** — `lo + hi` 可能超過 `int` 上限。
   標準寫法是 `lo + (hi - lo) / 2`。Python 的整數無上限，所以這題不會遇到，
   但 2.12 寫 C++ 版本時會。

## 延伸

這個模板之後會一直回來，而且外表會變得認不出來：

- **007-min-shipping-capacity（二分答案）**：你已經有這題了。那題的「陣列」是**虛構的**——
  索引是「載重上限」，`P(x) = 「載重 x 能在 days 天內運完嗎」`。
  `P` 是單調的（載重越大越容易達成），所以同一個模板直接套。
  做完這題再回去看 007，會覺得它變簡單了。
- **旋轉排序陣列**：陣列被切開重接，整體不再單調——但**局部還是**。
  這是 2.5 的下一題。
- **浮點二分**：區間是連續的，終止條件從 `lo < hi` 換成 `hi - lo > eps`
  或固定迭代次數。這是 2.5 的最後一題。
- **C++ 的 `std::lower_bound` / `upper_bound`**：回傳的是迭代器，
  要 `- v.begin()` 才變索引。2.12 會用到。
- **離散化**：把一堆雜亂的值排序去重，然後用 `lower_bound` 把原值映射成 `0..m-1` 的小整數。
  這是 2.6 和線段樹、以及很多計數問題的前置步驟。

**跟你的方向的關係**：點雲和影像特徵的最近鄰搜尋（KD-tree、八元樹）
本質上是把二分搜尋推廣到多維；而時間戳對齊——你在 055 寫過的
「給一個 IMU 時間找最接近的相機幀」——在實務上就是對時間戳陣列做 `lower_bound`，
然後比較左右兩個鄰居哪個更近。那題你用的是雙指標，
因為兩邊都有序且同向推進；但查詢是隨機順序時，就只能二分。
