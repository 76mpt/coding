# 022-entropy · 熵：換底與 0 log 0 — 參考解

## 標準解

```python
import math


def entropy(probs: list[float], base: float = 2) -> float:
    total = 0.0
    for p in probs:
        if p > 0:                          # 0 log 0 = 0，直接跳過
            total -= p * math.log(p, base)
    return total
```

O(n) 時間、O(1) 空間。

一行版：

```python
return -sum(p * math.log(p, base) for p in probs if p > 0)
```

## 換底公式

```
log_b(x) = ln(x) / ln(b)
```

**推導**：設 `y = log_b(x)`，依定義 `b^y = x`。兩邊取自然對數：

```
ln(b^y) = ln(x)
y · ln(b) = ln(x)          ← 用了 log(aⁿ) = n log a
y = ln(x) / ln(b)
```

所以底數只影響一個常數倍：

| 底 | 單位 | 換算 |
|---|---|---|
| 2 | bit（shannon） | 基準 |
| e | nat | `1 nat = 1/ln2 ≈ 1.443 bit` |
| 10 | dit（hartley） | `1 dit ≈ 3.32 bit` |

**換單位不改變任何比較結論**，因為所有分布的熵都乘上同一個常數。
ML 論文裡多半用 nat（因為微分方便），資訊理論教科書用 bit（因為有直觀意義）。

## `0 log 0 = 0` 為什麼合理

`log 0 = −∞`，所以 `0 × (−∞)` 是不定形式。但取極限：

```
lim_{p→0⁺} p · log p = 0
```

因為 `p` 趨近 0 的速度比 `log p` 趨近 −∞ 的速度**快**
（用羅必達法則：`log p / (1/p)` → `(1/p)/(−1/p²)` = `−p` → 0）。

**直覺解釋**：一個永遠不會發生的結果，對「平均不確定性」沒有貢獻。

程式上必須手動處理，因為 `math.log(0)` 拋例外。
NumPy 的做法通常是加一個小 epsilon 或用遮罩：

```python
import numpy as np
p = np.asarray(probs)
nz = p > 0
return -np.sum(p[nz] * np.log2(p[nz]))          # 遮罩，最乾淨

# 或者（不建議，會引入偏差）
return -np.sum(p * np.log2(p + 1e-12))
```

**加 epsilon 的做法會引入系統性偏差**，而且 epsilon 選多大是玄學。
能用遮罩就用遮罩。

## 熵的直覺

熵 = **平均需要幾個 bit 才能描述一次觀測結果**。

| 分布 | 熵（bit） | 意義 |
|---|---|---|
| `[1.0]` | 0 | 結果確定，不用傳任何資訊 |
| `[0.5, 0.5]` | 1 | 一個 bit（0 或 1） |
| `[0.25]×4` | 2 | 兩個 bit |
| `[0.9, 0.1]` | 0.469 | 大多數時候是同一個結果，可壓縮 |
| n 個等機率 | `log₂ n` | 最大值 |

**均勻分布的熵最大**，這是熵最重要的性質之一：
在只知道「有 n 種可能」的情況下，均勻分布是最「無知」的假設——
這就是**最大熵原理**，也是為什麼很多先驗分布選均勻。

Shannon 的**信源編碼定理**證明了：熵是無損壓縮的理論下限。
你不可能用少於 H 個 bit 平均編碼一個信源。

## 和 cross-entropy、KL 的關係

三個式子長得很像，差別要分清楚：

```
熵            H(p)     = −Σ p log p              「p 自己有多不確定」
交叉熵        H(p,q)   = −Σ p log q              「用 q 的編碼描述 p 要幾個 bit」
KL 散度       KL(p‖q)  = Σ p log(p/q)            「多付出的代價」
```

它們的關係是：

```
H(p, q) = H(p) + KL(p ‖ q)
```

在分類任務裡，`p` 是 one-hot 的真實標籤（熵 = 0），所以

```
cross-entropy loss = KL(p ‖ q)
```

**最小化交叉熵 = 最小化 KL 散度 = 讓預測分布逼近真實分布。**
這三件事在分類問題裡是同一件事，只是視角不同。

你在 M0.11 會正式練 KL，M4.1 會用互資訊（也是 log 的組合）做自監督學習。

## 常見錯誤

1. **忘記負號** — 得到的是負數。熵永遠 ≥ 0。
2. **沒處理 p = 0** — `math.log(0)` 拋 `ValueError: math domain error`。
   `[1.0, 0.0]` 那筆會抓到。
3. **`if p != 0`** — 通常可以，但如果有 `-0.0` 或極小負數（浮點誤差）會漏掉。
   用 `p > 0` 比較安全。
4. **底寫死成 2** — 忽略 `base` 參數，`base=math.e` 那筆不過。
5. **先正規化 probs** — 題目說總和約為 1，不需要你處理。**多做的事就是多錯的機會。**
6. **用 `math.log2(p) / math.log2(base)` 但寫反成 `math.log2(base) / math.log2(p)`** —
   換底公式的分子是「被取 log 的數」，分母是「底」。

## 延伸

熵在 CV / ML 的實際用途：

- **主動學習**：挑「模型最不確定」的樣本讓人標註 → 挑預測熵最高的
- **知識蒸餾**：溫度參數調整 soft label 的熵
- **決策樹**：資訊增益 = 分裂前的熵 − 分裂後的加權熵
- **模型校準**：預測熵太低 = 過度自信，這是深度網路的已知病症
- **資料集分析**：類別分布的熵可以量化「這個資料集有多不平衡」

最後一項你現在就能用：算出資料集類別分布的熵，除以 `log₂(類別數)`，
得到 0~1 的「平衡度」指標。低於 0.7 大概就要考慮重採樣了。
