# 062-first-bad-bracket · 找出第一個壞掉的括號 — 參考解

## 標準解

```python
def first_bad_bracket(s):
    PAIRS = {')': '(', ']': '[', '}': '{'}
    OPENERS = set(PAIRS.values())
    stack = []                                   # 還沒配對的左括號 (字元, 索引)

    for i, ch in enumerate(s):
        if ch in OPENERS:
            stack.append((ch, i))
        elif ch in PAIRS:
            if not stack or stack[-1][0] != PAIRS[ch]:
                return i                         # 壞右括號：立刻回報
            stack.pop()                          # 配對成功

    return stack[0][1] if stack else -1          # 最底層 = 最靠左的孤兒
```

時間 O(n)：每個字元進 stack 最多一次、出 stack 最多一次。空間 O(n)（全是左括號時）。

這已經是最佳解——你至少要看過每個字元一次。

## 為什麼是堆疊

括號配對有一個關鍵性質：**最近打開的，必須最先關閉**。

```
( [ )        ← 不合法：) 想關掉 (，但 [ 還開著
( [ ] )      ← 合法：後開的 [ 先關
```

「後進先出（LIFO）」正是堆疊的定義。**看到「必須先處理最近的那個」就該想到堆疊**，
這是這一節要你建立的直覺，而不是背「括號題用 stack」。

同一個直覺的其他場合：

- 函式呼叫：最近呼叫的函式最先返回——所以叫「呼叫堆疊（call stack）」
- 編輯器的 undo：最近做的動作最先被復原
- 運算式求值：`3 + 4 * 2`，`*` 比 `+` 晚進來但要先算

## 為什麼孤兒取 `stack[0]`

索引是遞增掃描的，所以推進 stack 的順序就是索引由小到大。
掃完之後 stack 裡剩下的都是沒配對的左括號，**最底層那個索引最小**。

`stack[-1]`（頂端）是最後開的那個，`stack[0]`（底部）才是題目要的最靠左。
`"([]"` 這個測資就是在抓這個：頂端是索引 1 的 `[`（但它已經被 pop 掉了），
剩下的只有索引 0——如果你寫 `stack[-1]` 在這裡剛好也對，
但 `"(([]"` 這種就會錯（正確 0，寫錯得到 1）。

## 另一種寫法：只存索引

```python
stack.append(i)                                  # 只存索引
...
if not stack or s[stack[-1]] != PAIRS[ch]:       # 需要字元時回頭查
    return i
```

少存一半的東西，需要字元時用 `s[索引]` 查回來。字串索引是 O(1)，沒有額外成本。
實務上兩種都常見；存 tuple 比較好讀，存索引比較省記憶體。

## 常見錯誤

1. **先取 `stack[-1]` 再檢查空不空**——`"())"` 直接 IndexError。
   Python 的 `or` 有短路求值，`if not stack or stack[-1][0] != ...` 的順序是對的；
   反過來寫就會炸。

2. **回傳 `stack[-1]` 的索引**——對稱的測資看不出來，`"(([]"` 會抓到。

3. **用計數器代替 stack**——只數左右括號的數量差。
   那只對單一種括號有效，`"([)]"` 的數量完全平衡，但它是壞的。
   **三種括號必須記住「誰在等」，不能只記「有幾個在等」。**

4. **配對表方向搞反**——`{'(' : ')'}` 然後查 `PAIRS[ch]`，遇到右括號會 KeyError。
   統一用「右括號 → 左括號」查起來最順，因為你是在看到右括號時才需要查。

5. **沒略過其他字元**——把字母也推進 stack，或是對字母做右括號的判斷。
   `"(a[b)c]d"` 會抓到。

6. **反覆刪除配對的字串**——`while '()' in s: s = s.replace('()', '')`。
   邏輯上可行，但每次 replace 都是 O(n)，最壞要做 n/2 次，整體 O(n²)。
   20 萬字元的測資會超時。

## 延伸

堆疊接下來會用在：

- **單調堆疊**（2.3 的下一題）：維護一個遞增或遞減的 stack，
  用來 O(n) 回答「每個元素右邊第一個比它大的是誰」。LeetCode 42 接雨水、739 每日溫度都是。
- **2.7 遞迴與回溯**：遞迴的本質就是編譯器幫你維護一個 stack。
  把遞迴改寫成迴圈時，你要自己把那個 stack 寫出來。
- **2.8 樹的走訪**：DFS 用 stack、BFS 用 queue。這兩個資料結構決定了你是「先走深」還是「先走寬」。

CV 裡最直接的是**解析巢狀格式**：COCO 標註是 JSON、KITTI 的校正檔、ROS 的 launch 檔，
任何一個解析器的最內層都在做這件事。你平常呼叫的 `json.loads` 裡面就有一個這樣的 stack。
