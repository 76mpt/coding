# 064-grid-shortest-path · 佔據網格上的最短路徑 — 參考解

## 標準解

```python
from collections import deque


def shortest_path(grid):
    m, n = len(grid), len(grid[0])
    if grid[0][0] == 1 or grid[m - 1][n - 1] == 1:
        return -1
    if m == 1 and n == 1:
        return 0

    seen = [[False] * n for _ in range(m)]
    seen[0][0] = True
    queue = deque([(0, 0, 0)])                      # (列, 行, 步數)

    while queue:
        r, c, d = queue.popleft()                   # 先進先出
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < m and 0 <= nc < n and grid[nr][nc] == 0 and not seen[nr][nc]:
                if nr == m - 1 and nc == n - 1:
                    return d + 1
                seen[nr][nc] = True                 # 入列時就標記
                queue.append((nr, nc, d + 1))

    return -1
```

時間 O(mn)：每格最多入列一次、出列一次，每次看四個鄰居。空間 O(mn)。

## 為什麼 BFS 給出的一定是最短路

關鍵是這個不變量：**佇列裡的步數永遠是非遞減的，而且最多只出現兩個相鄰的值 d 和 d+1。**

因為你總是從佇列前端取出步數為 d 的格子，往後端放步數 d+1 的格子。
所以整個搜尋是嚴格按層推進的：所有 d 步可達的格子處理完，才輪到 d+1 步的。

那麼第一次碰到終點時的步數，就不可能有更小的——如果存在一條 d' < d 的路徑，
終點早在處理第 d' 層時就被發現了。

**這個論證依賴「每步成本相同」。** 如果每格的通行成本不一樣（草地 1、沙地 3），
BFS 就不成立了，要改用 **Dijkstra**（把佇列換成優先佇列）——那是 2.9 堆積那節的內容。

## 為什麼堆疊不行

把 `popleft()` 換成 `pop()` 就變成 DFS（深度優先）。它仍然找得到路，**但不保證最短**：
DFS 會沿著一個方向一路衝到底，第一次抵達終點的路線可能繞了一大圈。

這是堆疊與佇列最根本的差別，也是這一節把兩者放在一起的原因：

| | 取出順序 | 搜尋形狀 | 找到的路 |
|---|---|---|---|
| 堆疊（DFS） | 後進先出 | 一條路走到底再回頭 | 不保證最短 |
| 佇列（BFS） | 先進先出 | 像水波一樣一圈圈擴散 | 等權重時保證最短 |

## 兩個效能陷阱

**1. 用 `list.pop(0)` 當佇列。** 功能正確，但 list 是連續記憶體，
從頭移除要把後面所有元素往前搬一格，單次 O(n)。整體從 O(mn) 變成 O((mn)²)，20 萬格必然超時。

`collections.deque` 是雙向鏈結的區塊結構，兩端都是 O(1)。
**看到「要從頭移除」就該用 deque**，這是 1.9 複雜度直覺那節的實際應用。

**2. 出列時才標記 visited。** 這是更隱蔽的錯：

```python
while queue:
    r, c, d = queue.popleft()
    if seen[r][c]:            # ← 出列才檢查
        continue
    seen[r][c] = True
```

功能仍然正確（答案對），但同一格可能被四個鄰居各放進佇列一次，
佇列長度從 O(mn) 膨脹到 O(4mn)，記憶體和常數項都變差。空曠的大網格會明顯變慢。

**入列即標記**是 BFS 的標準寫法。

## 常見錯誤

1. **忘了檢查起點或終點是障礙**——`[[1, 0], [0, 0]]` 會從障礙上出發。

2. **1×1 網格回傳 -1**——迴圈裡只檢查「鄰居是不是終點」，起點自己就是終點的情況沒被涵蓋。

3. **範圍檢查漏掉負數**——只寫 `nr < m and nc < n`。Python 的負索引不會報錯，
   `grid[-1]` 是最後一列，機器人會從上邊界穿到下邊界。

4. **在終點才回傳 `d`**——應該是 `d + 1`，因為那是再走一步才到的。
   或者改成「出列時檢查是不是終點」，那時才用 `d`。兩種寫法擇一，別混用。

5. **對角線也算鄰居**——題目說不能斜走。`[[0, 1], [1, 0]]` 應該是 -1，
   八方向會得到 1。

## 延伸

這題就是機器人導航最基礎的形式。真實系統往下長：

- **權重不同 → Dijkstra**（靠近障礙的格子成本高，路徑才不會貼牆走）
- **加上啟發式 → A\***（用曼哈頓距離估計「還要多遠」，優先展開有希望的方向，快很多）
- **格子換成連續空間 → RRT / PRM**（機械手臂、無人機的高維度空間沒辦法切格子）

CV 裡同一個 BFS 還會用在：

- **連通元件標記（connected components）**：二值化後找出每一塊前景，就是對每個沒訪問過的白點跑一次 BFS
- **距離變換（distance transform）**：從所有障礙點同時出發跑 BFS，得到每格離最近障礙有多遠——
  那是 ICP 配準和路徑規劃的常用前處理
