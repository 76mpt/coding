# 064-grid-shortest-path · 佔據網格上的最短路徑

- 階段：資料結構與演算法（LeetCode 風格） / 2.3 堆疊與佇列
- 語言：Python　難度：standard　互動方式：實作函式
- 要實作的入口：`shortest_path`
- 提示：共 4 階（`python trainer.py hint 064-grid-shortest-path`）
- 測資：13 筆（`python trainer.py test 064-grid-shortest-path`）

────────────────────────────────────────────────────────────────────

機器人拿到一張**佔據網格（occupancy grid）**：`0` 是可通行、`1` 是障礙物。
它要從左上角 `(0, 0)` 走到右下角 `(m-1, n-1)`，每步只能上下左右移動一格，不能斜走，不能踩障礙。

實作 `shortest_path(grid)`，回傳最少要走幾**步**；走不到就回傳 `-1`。

「步數」是移動的次數，不是經過的格子數。起點就是終點時回傳 `0`。

**範例**

```python
shortest_path([[0, 0, 0],
               [1, 1, 0],
               [0, 0, 0]])        ->  4
```

路線是右、右、下、下，共 4 步。

```python
shortest_path([[0, 1],
               [1, 0]])           ->  -1      # 被對角的障礙封死，不能斜走
shortest_path([[0]])              ->  0       # 起點就是終點
shortest_path([[1, 0], [0, 0]])   ->  -1      # 起點本身是障礙
shortest_path([[0, 0], [0, 1]])   ->  -1      # 終點是障礙
```

**限制**
- `1 <= m, n`，格子總數 `m * n <= 2 * 10^5`
- 每格是 `0` 或 `1`
- 回傳 `int`

**效能要求**：大測資有 20 萬格與時間上限。
每一格只能被處理常數次——**走過的格子要記得標記**，不然同一格會被反覆放進待辦清單，
指數級爆炸，連小測資都跑不完。

這題要用**佇列（queue）**：先進先出。
為什麼不能用上一題的堆疊？想一想——如果先處理最晚放進去的格子，你會一路衝到底再回頭，
那樣第一次抵達終點的路線**不保證最短**。
佇列讓你「先走完所有 1 步能到的格子，再走 2 步的」，第一次碰到終點就是答案。
