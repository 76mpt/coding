# 050-harmonic-and-logn · 調和級數與 log n 的來源 — 參考解

## 標準解

```python
import math

GAMMA = 0.5772156649015329


def series_facts(n):
    h = 0.0
    for k in range(1, n + 1):
        h += 1 / k

    err = None if n == 0 else h - (math.log(n) + GAMMA)

    m = n                        # 複製，不要動到 n
    steps = 0
    while m > 1:
        m //= 2
        steps += 1

    return h, err, steps
```

## 「每項趨近 0」不等於「級數收斂」

這是這題最重要的一句話。

```
Σ 1/2ᵏ   每項趨近 0  →  收斂到 2      （等比，上一題）
Σ 1/k    每項趨近 0  →  發散到 ∞      （調和，這題）
Σ 1/k²   每項趨近 0  →  收斂到 π²/6
```

**趨近 0 是收斂的必要條件，不是充分條件。** 關鍵在**趨近的速度**：

| 級數 | 通項 | 收斂？ |
|---|---|---|
| `Σ rᵏ`（\|r\|<1） | 指數衰減 | ✅ |
| `Σ 1/k^p`，p > 1 | 多項式衰減，夠快 | ✅ |
| `Σ 1/k` | 多項式衰減，剛好不夠快 | ❌ |
| `Σ 1/(k ln k)` | 更慢 | ❌ |

**`p = 1` 是分水嶺**。這條分界線在機器學習裡直接出現：
**梯度下降的學習率排程 `ηₖ = 1/k` 滿足 `Σηₖ = ∞`（走得夠遠）
且 `Σηₖ² < ∞`（雜訊被壓下去）**——那正是隨機梯度下降收斂的經典條件（Robbins–Monro）。

**它同時用到調和級數發散和平方級數收斂**，兩個都是這題的內容。

## 分組證明

```
1  +  1/2  +  (1/3+1/4)  +  (1/5+…+1/8)  +  (1/9+…+1/16)  + …
              ↑ > 2×1/4     ↑ > 4×1/8      ↑ > 8×1/16
              = 1/2         = 1/2          = 1/2
```

第 j 組有 `2^(j−1)` 項，每項都 `> 1/2ʲ`，所以每組 `> 1/2`。
**組數無限多 → 總和無上界。**

而 n 項大約分成 `log₂ n` 組，每組貢獻約 1/2，所以 `H_n ≈ (log₂ n)/2`——
量級對了（真值是 `ln n`，差在常數）。

## `H_n ≈ ln(n) + γ` 的精確度

實測誤差：

```
n = 1        誤差 4.2e-01
n = 10       誤差 4.9e-02
n = 1000     誤差 5.0e-04
n = 100000   誤差 5.0e-06
```

**誤差 ≈ 1/(2n)**——n 放大 100 倍，誤差縮小 100 倍。

 γ（歐拉–馬斯凱羅尼常數）就定義成 `lim (H_n − ln n)`。
它是數學裡最著名的未解問題之一：**沒有人知道 γ 是不是無理數**。

直觀上 `H_n ≈ ln n` 是因為 `Σ 1/k` 是 `∫ dx/x = ln x` 的離散版本——
**求和是積分的離散版，這個對應在 M1.5 傅立葉、M5.2 隨機過程會反覆出現**。

## 為什麼砍半次數是 `floor(log₂ n)`

```
n → n//2 → n//4 → … → 1
```

砍 k 次剩下約 `n/2ᵏ`，要它 `= 1` 就是 `k = log₂ n`。整數除法會下取整，所以是 `floor`。

驗算幾個：

| n | 砍法 | 次數 | `floor(log₂ n)` |
|---|---|---|---|
| 1 | — | 0 | 0 |
| 3 | 3→1 | 1 | 1 |
| 10 | 10→5→2→1 | 3 | 3 |
| 1000 | … | 9 | 9 |
| 10⁶ | … | **19** | 19 |

**一百萬個元素，二分搜尋只要 19 步。** 這個數字值得記住——
它是「為什麼 O(log n) 幾乎等於免費」的具體感受。

這個 `log n` 出現在：二分搜尋（2.5）、平衡樹高度（2.8）、
堆積的 sift 操作（2.9）、合併排序的層數（2.6）、線段樹（3.8）。
**全部都是「每次砍一半」。**

## Σ 的操作規則（這節的另一半）

讀論文公式時最常用的三條：

```
1. 提出常數      Σ c·aᵢ = c·Σ aᵢ
2. 拆開加法      Σ (aᵢ + bᵢ) = Σaᵢ + Σbᵢ
3. 交換順序      Σᵢ Σⱼ aᵢⱼ = Σⱼ Σᵢ aᵢⱼ
```

第 3 條在程式裡就是「先走列還是先走行，總和一樣」——
你在 034 手寫矩陣乘法時，那個 `Σₖ` 就是被交換順序的對象。

**這三條是「讀懂公式」的識字能力**。M0.8 手推反向傳播時，
整個推導就是反覆用第 1 和第 3 條把和式重新排列。

## 常見錯誤

1. **`while m > 0`** —— 多算一次。問的是「砍到剩 1」不是「砍到剩 0」。`n=1` 該回 0。
2. **用 `/` 而不是 `//`** —— 浮點數永遠除不到 1，無窮迴圈。
3. **直接改 `n` 而不複製** —— 第三項算完之後 `n` 變成 1，如果第二項寫在後面就會用到錯的 n。標準解用 `m = n` 避開。
4. **`range(0, n+1)`** —— `1/0` 直接 ZeroDivisionError。要從 1 開始。
5. **`range(1, n)`** —— 少算最後一項。要 `n+1`。
6. **`n=0` 沒擋 `math.log(0)`** —— 拋 `ValueError: math domain error`（你在 021 遇過同一個錯誤）。

## 延伸

調和級數的實際出場：

| 場景 | 為什麼是 H_n |
|---|---|
| **快速排序的平均比較次數** | `2n ln n`，來自 H_n |
| **優惠券收集問題** | 收集 n 種要買 `n·H_n ≈ n ln n` 次 |
| **SGD 學習率 1/k** | `Σ 1/k = ∞` 保證走得夠遠 |
| **Zipf 分布** | 詞頻正比於 `1/rank`，正規化常數就是 H_n |

最後一條跟 NLP 直接相關：自然語言的詞頻大致服從 Zipf 定律，
**所以詞彙表的涵蓋率增長是對數的**——這就是為什麼再多加詞彙，涵蓋率也上不去。
