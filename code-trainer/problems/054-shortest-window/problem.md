# 054-shortest-window · 最短的達標區間

- 階段：資料結構與演算法（LeetCode 風格） / 2.1 陣列與雙指標
- 語言：Python　難度：standard　互動方式：實作函式
- 要實作的入口：`shortest_window`
- 提示：共 4 階（`python trainer.py hint 054-shortest-window`）
- 測資：10 筆（`python trainer.py test 054-shortest-window`）

────────────────────────────────────────────────────────────────────

你在分析一段影片的逐幀偵測數量。`counts[i]` 是第 i 幀偵測到的物件個數，
全部是**非負整數**。

你想找出最短的一段**連續幀**，讓這段裡面的偵測總數 `>= target`。

實作 `shortest_window(counts, target)`，回傳那段的**長度**。
找不到任何一段就回傳 `0`。

**範例**

```python
shortest_window([2, 3, 1, 2, 4, 3], 7)   ->  2      # [4, 3] 加起來 7，長度 2
shortest_window([1, 4, 4], 4)            ->  1      # 單獨一個 4 就夠了
shortest_window([1, 1, 1, 1], 11)        ->  0      # 全部加起來才 4，湊不到
shortest_window([5], 5)                  ->  1
```

第一個範例值得多看一眼：`[3, 1, 2, 4]` 加起來是 10，也 `>= 7`，但長度是 4。
`[2, 4, 3]` 是 9，長度 3。最短的是 `[4, 3]`，長度 2。
**你要的是最短的，不是第一個找到的。**

**限制**
- `0 <= n <= 2 * 10^5`
- `0 <= counts[i] <= 10^4`，`1 <= target <= 10^9`
- `counts` 可能是空陣列，這時回傳 `0`
- 區間必須是**連續**的，不能跳著挑

**效能要求**：測資裡有一筆 n = 200,000 的大測資與時間上限。
枚舉所有 `(左界, 右界)` 是 O(n²) ≈ 4×10^10 次運算，必然超時。
這題的重點是想出 **O(n)** 的做法。

提醒一件事：所有元素都是**非負**的。這個條件不是隨便給的，
它讓「往右擴張區間和只會變大或不變，往右收縮只會變小或不變」成立——
這正是這題能用 O(n) 解的原因。想清楚這句話，做法就出來了。
