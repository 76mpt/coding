光達或深度相機一次吐出幾十萬個 3D 點，大部分擠在一起、彼此只差幾公釐。
SLAM 前處理的標準第一步是**體素降採樣（voxel downsampling）**：
把空間切成邊長 `size` 的小立方體，**每個立方體裡的所有點合併成一個點**——它們的平均位置。

點 `(x, y, z)` 落在哪個體素，由它的**體素座標**決定：

```
(⌊x / size⌋, ⌊y / size⌋, ⌊z / size⌋)
```

`⌊ ⌋` 是**往下取整（floor）**：`⌊2.7⌋ = 2`，`⌊-0.4⌋ = -1`。

實作 `voxel_downsample(points, size)`，回傳 `(體素座標, 中心點)`：

- **體素座標**：所有非空體素，每個是 `[i, j, k]` 三個整數，**由小到大排序**（先比 i，再比 j，再比 k）
- **中心點**：跟體素座標一一對應，每個是該體素內所有點的平均 `[x, y, z]`

**範例**

```python
points = [[0.1, 0.2, 0.3], [0.4, 0.1, 0.2], [1.2, 0.3, 0.1], [-0.2, 0.1, 0.1]]
voxel_downsample(points, 0.5)
->  ( [[-1, 0, 0], [0, 0, 0], [2, 0, 0]],
      [[-0.2, 0.1, 0.1], [0.25, 0.15, 0.25], [1.2, 0.3, 0.1]] )
```

前兩個點都落在 `[0, 0, 0]`，合併成它們的平均。
最後一個點 x = -0.2：`-0.2 / 0.5 = -0.4`，往下取整是 **-1**，不是 0。

**限制**
- `0 <= len(points) <= 2 * 10^5`；沒有點的時候回傳 `([], [])`
- 座標是 float，可能是負數
- `size` 是 `0.25`、`0.5`、`1`、`2` 這類 2 的次方，除法不會碰到浮點誤差
- 中心點的比對容許 `1e-9` 的誤差

**效能要求**：大測資有 200,000 個點與時間上限。
對每個點都去掃一遍「目前已經有的體素」看自己屬於哪一個，是 O(n × 體素數)，會超時。

這題的 key 是一個 **tuple**。做之前先想清楚兩件事：
為什麼 list 不能當 dict 的 key？以及負數的「往下取整」為什麼不能用 `int()`？
