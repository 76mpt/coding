# 074-max-cut-length · 裁出等長片段的最大長度 — 參考解

## 標準解

```python
def max_cut_length(lengths, k):
    def pieces(x):
        return sum(int(L / x) for L in lengths)     # 單調遞減

    lo, hi = 0.0, max(lengths)          # lo 側可行，hi 側不可行
    for _ in range(100):                # 固定輪數：誤差 = 初始區間 × 2^-100
        mid = (lo + hi) / 2
        if pieces(mid) >= k:            # mid 可行 → 答案 >= mid
            lo = mid
        else:
            hi = mid
    return lo
```

十行。這題的難度完全不在程式，在於認出「這是一個二分答案題」
以及處理實數區間的收尾。

## 為什麼固定迭代次數比 `eps` 好

`while hi - lo > eps` 有兩個麻煩：

1. **`eps` 難挑。** 答案可能是 `0.001`，也可能是 `10000`。
   絕對誤差 `1e-9` 對前者過嚴（可能在浮點精度下永遠達不到 → 無窮迴圈），
   對後者又鬆到不夠精確。要寫對就得改成相對誤差，程式變複雜。
2. **可能根本不終止。** 當 `lo` 和 `hi` 是相鄰的浮點數時，
   `(lo + hi) / 2` 會剛好等於其中一個，區間再也不變小。
   如果你的 `eps` 比那個間距還小，迴圈就永遠跑不完。

固定輪數把這兩個問題一次解決：**n 輪之後誤差嚴格是初始區間的 `2^(-n)`**，
可以事先算出來，而且不管答案大小都成立（這是絕對誤差；
要相對誤差就改成對 `log x` 二分，但這題不需要）。

100 輪在雙精度下其實早就超過浮點數能表示的精度了（約 53 位，即 `2^-53`），
所以 60 輪之後 `lo` 就不再變化。寫 100 只是圖個整數好記。

## 答案一定是某個 `lengths[i] / j`

這個性質值得知道，因為它是**驗證測資正確性的方法**。

固定一段長度 `L`，看 `floor(L/x)` 怎麼隨 `x` 變化：

```
floor(L/x) = j   ⟺   j <= L/x < j+1   ⟺   L/(j+1) < x <= L/j
```

所以 `floor(L/x)` 在半開區間 `(L/(j+1), L/j]` 上是常數 `j`，
而且**恰好在 `x` 超過 `L/j` 的瞬間掉下來**。

`pieces(x)` 是這些階梯函數的和，所以它也是階梯函數，
它的「掉下去的點」全都落在 `{L_i / j}` 這個集合裡。
而我們要的是「最大的可行 `x`」——可行區是左邊一整段，
它的右端點必定是某個階梯的頂端，也就是某個 `L_i / j`。

**所以這題的精確答案是一個有理數。** 我在出這題時就是用這個性質驗證測資的：
把所有 `lengths[i]` 轉成 `Fraction`，窮舉所有候選 `L_i / j`，
用**精確有理數算術**檢查可行性，取最大的那個。
那條路完全不碰浮點數，跟二分搜尋沒有任何共用程式碼，
所以它能獨立證明每一筆期望值是對的。
（但它是 `O(m·k)`，`k = 2×10^5` 時不可能跑——這就是為什麼你得二分。）

## 浮點數的陷阱

`int(L / x)` 在 `x` 非常接近 `L/j` 的時候可能給出 `j` 或 `j-1`，取決於捨入。
例如 `int(1.0 / 0.1)` 在某些值上會是 9 而不是 10，因為 `0.1` 不是精確的二進位小數。

這題不會因此出錯，原因是**二分搜尋對 `pieces` 在單點上的誤判是免疫的**：
如果 `pieces` 在分界點附近偶爾判錯一次，二分只是收斂到一個差了 `2^-n` 的位置，
而那個誤差遠小於要求的 `1e-6`。

但這個免疫不是白來的——它靠的是「答案允許有容差」。
如果題目要你回傳精確的 `j`（片段數）或精確的有理數，就得用上面那條精確路線。
**知道哪些誤差會被吸收、哪些不會，是浮點程式的核心判斷力。**

## 複雜度

- 時間 **O(m · 輪數)** = `5000 × 100 = 5×10^5` 次除法
- 空間 **O(1)**

窮舉候選是 `O(m·k)` 次可行性檢查，每次又是 `O(m)`——完全不可行。

## 常見錯誤

1. **二分方向寫反** — `pieces(mid) >= k` 時收 `hi = mid`。
   這會收斂到「最小的可行 x」，但那是 0。
   `[1,1,1,1]` 配 `k = 4` / `k = 5` 兩筆答案差一倍，方向反了會對調，立刻現形。
2. **最後回傳 `hi`** — `hi` 是從不可行側逼近的那一個。誤差只有 `2^-100`，
   所以這題**碰巧**也會過（容差 `1e-6`）。但觀念是錯的：
   在整數版本（007）回傳錯的那一側會直接答錯。養成回傳可行側的習慣。
3. **用 `while hi - lo > eps`，`eps` 寫死 `1e-9`** — 答案接近 `10^4` 時，
   相鄰浮點數的間距約 `2×10^-12`，勉強跑得完；但換成 `1e-12` 就卡死。
   這種 bug 在本機跑得過、在評測機上超時，很難查。
4. **上界設成 `sum(lengths)`** — 不會錯，只是多浪費幾輪（區間大了幾千倍，
   多 12 輪左右）。但如果你用的是 `eps` 版本，區間變大就更容易踩到第 3 點。
   上界設 `max(lengths)` 才是緊的。
5. **沒檢查「兩端一可行一不可行」這個前提** — `k = 1` 時答案就是 `max(lengths)`，
   而 `max(lengths)` 本身**是可行的**（最長那段剛好裁出 1 片）。
   也就是說「`hi` 側一定不可行」在 `k = 1` 時並不成立。
   這題仍然會過，因為我們回傳 `lo`，它從下方逼近 `max(lengths)`，
   誤差是 `2^-100` 級別，遠在容差內。
   但值得記住：**二分的前提要自己驗一次**，不要因為這次僥倖過關就以為它成立。
   整數版本沒有容差兜著，同樣的疏忽就會答錯。
6. **`pieces` 用浮點數累加** — `sum(L / x for L in lengths)` 漏掉了 `floor`。
   裁片段不能裁出半片，`floor` 是題目的核心，拿掉就變成完全不同的問題
   （而且那個問題有閉式解 `sum(lengths)/k`，不需要二分）。

## 延伸

**2.5 收齊了。** 四題各打一個技能點：

- **072-search-bounds**：真實陣列上的 `lower_bound` / `upper_bound`，模板的本體
- **073-search-rotated**：陣列被旋轉，單調性要自己找回來
- **007-min-shipping-capacity**：虛構的整數陣列（二分答案）
- 這題：虛構的**實數**區間（浮點二分）

四個外表完全不同，骨架是同一個：**找單調條件的分界點**。

接下來值得知道的：

- **最大平均值子陣列**（LeetCode 644）：求長度至少 `L` 的連續子陣列，平均值最大。
  二分答案 `x`，然後問「存在子陣列使 `Σ(aᵢ − x) >= 0` 嗎」——
  減掉 `x` 之後問題就變成 2.2 的前綴和。
  這類「把分數式變成減法」的技巧叫 **0-1 分數規劃**，是浮點二分最漂亮的應用。
- **Dinkelbach 演算法**：同一類問題的牛頓法版本，收斂比二分快得多。

**跟你的方向的關係**：浮點二分在 CV 裡最常見的用途是**選閾值**。
RANSAC 要決定「多近才算 inlier」、特徵匹配要決定距離比值的門檻，
這些都是「給定閾值 x，算出某個數量，要它達到目標」的形式——
只要那個數量對 x 單調，就是這題。
另外，單目 SLAM 的尺度估計、以及把深度圖對齊到真實尺度，
也常寫成「二分那個尺度因子，直到重投影誤差的某個統計量達標」。
