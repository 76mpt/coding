這題是最後一種的連續版本：**要搜尋的區間是實數，不是整數**。

你錄了 m 段長度不一的軌跡，`lengths[i]` 是第 i 段的長度（正的浮點數）。
現在要從這些軌跡裡裁出 **`k` 段等長**的片段當訓練樣本：

- 每一段軌跡可以裁成好幾個片段，裁完剩下的零頭直接丟掉
- 不同軌跡裁出來的片段**不能接起來**
- 所有片段的長度必須完全一樣

長度訂得越短，裁得出來的片段越多；訂得越長，片段越少。
問：在還能裁出至少 `k` 段的前提下，**片段長度最長可以是多少**？

寫成式子：求最大的 `x > 0` 使得

```
Σᵢ floor(lengths[i] / x) >= k
```

實作 `max_cut_length(lengths, k)`，回傳那個最大的 `x`（float）。

**範例**

```python
max_cut_length([8, 4, 2], 3)            -> 4.0
# x = 4：8 裁出 2 段、4 裁出 1 段、2 裁出 0 段，共 3 段。
# x 再大一點（比如 4.01），8 只裁得出 1 段、4 裁不出來 → 總共 1 段，不夠。

max_cut_length([10, 5, 25, 15, 1], 5)   -> 8.333333...   （= 25/3）
# x = 25/3：10→1 段、5→0 段、25→3 段、15→1 段、1→0 段，共 5 段。

max_cut_length([7.5], 3)                -> 2.5
max_cut_length([1, 1, 1, 1], 5)         -> 0.5
# 四段長度 1 的軌跡，每段只裁一次只有 4 段，不夠 5；
# 所以每段至少要裁兩次 → x 最多 0.5。
```

## 連續區間上的二分要換一套收尾

整數二分有個好東西：區間每輪至少縮小 1，所以 `lo == hi` 時一定結束。
實數沒有這個保證——`lo` 和 `hi` 可以無限接近而永遠不相等，
浮點數下 `(lo + hi) / 2` 甚至可能等於 `lo` 或 `hi`，寫成 `while lo < hi` 就是無窮迴圈。

所以終止條件必須換掉。`while hi - lo > eps` 可以，但 `eps` 難挑：
答案可能是 0.001 也可能是 10000，絕對誤差和相對誤差要的 `eps` 差很多。

**更好的做法是固定迭代次數。** 每一輪區間減半，所以 n 輪之後誤差是初始區間的 `2⁻ⁿ`。
算一下這題要幾輪就夠——`2⁻ⁿ` 要小於要求的精度——你會發現那個數字小得令人安心，
而且完全不用猜 `eps`。這是浮點二分的標準寫法，值得記住。

另外注意單調性的方向變了：`x` **越大**，片段數**越少**。
所以可行的那一側是左邊，`lo` 才是答案的候選。寫之前先想清楚哪一邊該往裡收。

**限制**
- `1 <= m <= 5000`，`1 <= k <= 10^6`
- `lengths[i]` 是正浮點數，最大不超過 `10^4`
- **保證答案 >= 1e-3**
- 容差 `1e-6`（相對或絕對）
- 100 輪二分就足夠達到這個精度，不需要更多
- 大測資有時間上限：`m = 5000`、`k = 2×10^5`。
