# 063-next-stronger-frame · 下一個更有信心的幀 — 參考解

## 標準解

```python
def next_stronger(scores):
    result = [-1] * len(scores)
    stack = []                                   # 還在等答案的索引，分數由底到頂遞減

    for j, x in enumerate(scores):
        while stack and scores[stack[-1]] < x:   # x 能解決頂端那個
            result[stack.pop()] = j
        stack.append(j)                          # 換 j 自己去等

    return result
```

時間 **O(n)**，空間 O(n)。

## 為什麼是 O(n) 而不是 O(n²)

程式裡有巢狀迴圈，但複雜度不是 O(n²)。理由是**每個索引一輩子只會被 push 一次、pop 一次**：

- push：外層迴圈每個 j 執行一次 → 總共 n 次
- pop：只能對已經 push 的元素做，所以最多 n 次

內層 `while` 的總執行次數 = 總 pop 次數 ≤ n。外層 n 次加內層總共 n 次，整體 O(n)。

這叫**攤還分析（amortized analysis）**：不看單次最壞情況，看「總共做了多少事」。
054 的滑動視窗也是同樣的論證（左指標只往右走，最多走 n 步）。
**面試時這是必問的追問**——看到巢狀迴圈就說 O(n²) 會被抓包。

## 為什麼堆疊是遞減的（正確性論證）

宣稱：任何時刻，堆疊由底到頂的分數**嚴格遞減**。

用歸納法。推入 j 之前，`while` 已經把所有「分數 < `scores[j]`」的頂端元素彈光了，
所以此時堆疊頂端的分數 ≥ `scores[j]`，推入之後仍然遞減（或相等——
相等時不彈出是刻意的，因為題目要「嚴格大於」才算答案）。

有了這個性質，正確性就顯然了：`scores[j]` 要找的「能被它解決的索引」全部集中在堆疊頂端連續一段，
遇到第一個 ≥ 自己的就可以停——**底下的只會更大，不可能被解決**。
這就是為什麼不用掃整個堆疊。

## 常見錯誤

1. **用 `<=` 比較**——變成「大於或等於」就算答案。`[2, 2, 3]` 的索引 0 會填 1 而不是 2。

2. **內層用 `if` 不是 `while`**——一次只解決一個。`[4, 3, 2, 1, 5]` 只有索引 3 會被填到，
   0、1、2 全是 -1。

3. **堆疊存分數而不是索引**——`stack.append(x)`。比較是對的，但你不知道要填 `result` 的哪一格。
   （存 `(分數, 索引)` 的 tuple 也可以，只是多存一份。）

4. **`result[i] = scores[j]`**——填成了分數。題目要的是**索引**。

5. **反向掃描時邊界寫錯**——見下面的另一種寫法，`range(n - 1, -1, -1)` 的第二個 `-1` 常被寫成 `0`，
   那樣索引 0 會被漏掉。

## 另一種寫法：從右往左掃

```python
def next_stronger(scores):
    n = len(scores)
    result = [-1] * n
    stack = []                                   # 右邊「可能成為答案」的候選索引
    for i in range(n - 1, -1, -1):
        while stack and scores[stack[-1]] <= scores[i]:
            stack.pop()                          # 不夠大，永遠用不到了
        if stack:
            result[i] = stack[-1]
        stack.append(i)
    return result
```

一樣 O(n)。差別在觀點：

- **從左往右**：堆疊裝「還在等答案的人」，新元素**回頭去填**答案
- **從右往左**：堆疊裝「未來的候選答案」，新元素**往前查**自己的答案

注意這版的比較要用 `<=`（把不夠大的候選丟掉），跟正向版的 `<` 剛好相反——
很容易寫混。挑一種寫熟就好，我建議正向版，因為它比較容易推廣到「同時要知道左右兩邊」的題目。

## 延伸

單調堆疊是一個模式，不是一道題。看到「**對每個元素，找它左邊／右邊第一個比它大／小的**」就是它：

- **LeetCode 739 每日溫度**：這題換個包裝，答案填的是距離 `j - i` 而不是索引 j
- **LeetCode 84 柱狀圖最大矩形**：對每根柱子找左右第一個比它矮的，中間那段就是它能撐開的寬度
- **LeetCode 42 接雨水**：每個凹槽的水量由左右兩邊的邊界決定

CV 裡最直接的對應是**一維訊號的極值與谷底偵測**：
追蹤器的信心曲線、光流的殘差曲線、SLAM 的重投影誤差隨時間變化——
要找「什麼時候開始變差、變差了多久才恢復」，就是這個模式。

2.3 的最後一題會換成另一種容器：**佇列**（先進先出），用來做廣度優先搜尋。
