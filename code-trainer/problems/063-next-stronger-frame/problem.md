# 063-next-stronger-frame · 下一個更有信心的幀

- 階段：資料結構與演算法（LeetCode 風格） / 2.3 堆疊與佇列
- 語言：Python　難度：standard　互動方式：實作函式
- 要實作的入口：`next_stronger`
- 提示：共 4 階（`python trainer.py hint 063-next-stronger-frame`）
- 測資：12 筆（`python trainer.py test 063-next-stronger-frame`）

────────────────────────────────────────────────────────────────────

追蹤器每一幀給出一個信心分數 `scores[i]`。分數掉下去的時候，你想知道
**還要等多久才會再出現一個比現在更有信心的幀**——等太久就代表追丟了，該重新初始化。

實作 `next_stronger(scores)`，回傳一個跟輸入等長的 list：
第 i 個元素是「**從 i 往右數，第一個分數嚴格大於 `scores[i]` 的索引**」，
右邊都沒有更大的就填 `-1`。

**範例**

```python
next_stronger([3, 1, 4, 2])        ->  [2, 2, -1, -1]
```

- `i=0`（分數 3）：往右找到索引 2 的 4
- `i=1`（分數 1）：往右第一個更大的也是索引 2
- `i=2`（分數 4）：右邊沒有比 4 大的 → -1
- `i=3`（分數 2）：右邊沒東西 → -1

```python
next_stronger([5, 4, 3])           ->  [-1, -1, -1]    # 一路遞減
next_stronger([1, 2, 3])           ->  [1, 2, -1]      # 一路遞增
next_stronger([2, 2, 3])           ->  [2, 2, -1]      # 相等不算「更大」
next_stronger([])                  ->  []
```

第四個例子要注意：題目要的是**嚴格大於**，所以索引 0 的 2 不會被索引 1 的 2 滿足。

**限制**
- `0 <= n <= 2 * 10^5`
- `-10^9 <= scores[i] <= 10^9`，可能有負數與重複值
- 回傳 `list[int]`，長度等於 `len(scores)`

**效能要求**：大測資 n = 200,000 並有時間上限。
對每個 i 都往右掃一遍是 O(n²) ≈ 2×10^10 次運算，必然超時。

這題的關鍵在於看出**誰在等**。往右走的時候，前面那些「還沒等到更大值」的索引會累積起來；
一旦來了一個大數，它可能一口氣解決好幾個等待中的索引——而且**解決的順序是從最近的開始**。
又是「先處理最近的那一個」，所以又是堆疊。
