# 060-gram-schmidt · Gram-Schmidt 正交化 — 參考解

## 標準解

```python
def gram_schmidt(vectors):
    def dot(a, b):
        return sum(x * y for x, y in zip(a, b))

    Q = []
    for v in vectors:
        w = [float(x) for x in v]
        for q in Q:
            c = dot(q, v)                               # v 在 q 方向上的投影係數
            w = [wi - c * qi for wi, qi in zip(w, q)]   # 扣掉那一段
        length = dot(w, w) ** 0.5
        Q.append([wi / length for wi in w])             # 縮放成單位向量

    G = [[dot(a, b) for b in Q] for a in Q]
    rebuilt = [[sum(dot(q, v) * q[i] for q in Q) for i in range(len(v))]
               for v in vectors]
    return Q, G, rebuilt
```

時間 O(k² n)：第 j 個向量要跟 j−1 個 q 做內積，每次 O(n)。

## 推導：為什麼 w 跟所有之前的 q 都垂直

用歸納法。假設 `q₁ … qⱼ₋₁` 已經兩兩垂直且長度為 1。令

```
wⱼ = vⱼ − Σᵢ₌₁^{j−1} (qᵢ·vⱼ) qᵢ
```

對任一 `m < j`：

```
qₘ · wⱼ = qₘ·vⱼ − Σᵢ (qᵢ·vⱼ)(qₘ·qᵢ)
        = qₘ·vⱼ − (qₘ·vⱼ)·1          ← 只有 i = m 那項的 qₘ·qᵢ 不是 0
        = 0
```

所以 `wⱼ` 跟所有之前的 q 垂直，縮放成 `qⱼ` 之後仍然垂直，歸納成立。

`wⱼ ≠ 0` 由線性獨立保證：如果 `wⱼ = 0`，`vⱼ` 就能寫成 `q₁ … qⱼ₋₁` 的線性組合，
而那些 q 又都是 `v₁ … vⱼ₋₁` 的線性組合——跟線性獨立矛盾。

## 為什麼 G 和 rebuilt 能證明你算對了

這兩個檢查剛好對應正交單位基底的兩個要求：

- **`G = I` 檢查「正交單位」**：對角線 `qᵢ·qᵢ = 1` 代表長度是 1；非對角線 `qᵢ·qⱼ = 0` 代表垂直。
  如果你漏扣了某個投影，對應的非對角線就不會是 0。

- **`rebuilt = vectors` 檢查「張成同一個空間」**：Q 如果正交但方向算錯了（例如扣投影時用錯了向量），
  它們張成的會是另一個空間，原向量就組不回來。

兩個檢查缺一不可：只看 `G`，一組跟原向量毫無關係的正交基底也會過；
只看 `rebuilt`，一組沒有正交化的基底也可能組得回來。

## QR 分解：rebuilt 的係數就是 R

仔細看 `rebuilt` 用的係數 `qᵢ·vⱼ`。把它排成矩陣 `R[i][j] = qᵢ·vⱼ`：

- 當 `i > j` 時，`vⱼ` 只由 `q₁ … qⱼ` 組成，而 `qᵢ` 跟它們都垂直，所以 `R[i][j] = 0`
- 所以 **R 是上三角矩陣**

而 `rebuilt = vectors` 用矩陣寫就是 **`A = Q R`**（把 v 們當成行排成 A）。

你剛剛寫的就是 **QR 分解**。`np.linalg.qr(A)` 做的是同一件事。

但如果你拿 numpy 的結果跟你的比，**Q 的某些行可能差一個負號**。
QR 分解在「R 對角線要是正數」這個約定之下才唯一，numpy 底層的 LAPACK 不保證這個約定。
這就是為什麼這題的測資不直接跟 numpy 比，而是驗證 `G = I` 和 `rebuilt = vectors` 這兩個**性質**——
性質不會因為符號約定而改變。

## 修正版 Gram-Schmidt

```python
for q in Q:
    c = dot(q, w)                  # ← 用扣到一半的 w，不是原本的 v
    w = [wi - c * qi for wi, qi in zip(w, q)]
```

數學上完全相等（因為 w 跟之前的 q 已經垂直，`q·w = q·v`）。但浮點數下不一樣：

- **古典版**：每個係數都拿原始的 v 算。前面的 q 如果因為浮點誤差不是完全正交，
  誤差會在每一步**累積**，向量一多、接近相依時，最後的 Q 會明顯不正交
- **修正版**：每一步都拿「已經扣掉前面投影」的 w 算，前一步的誤差會在下一步被**修正**掉

這題向量少、離相依很遠，兩種都過。但實務上一律用修正版，或直接用 Householder 反射（numpy 的做法）。
這跟 048「同一條數學式，不同計算順序有不同的數值可靠度」是同一個道理。

## 常見錯誤

1. **只扣前一個 q 的投影**——`w = v − (qⱼ₋₁·v) qⱼ₋₁`。兩個向量時對，三個以上 `G` 的非對角線就不是 0。

2. **忘了正規化**——`Q.append(w)`。`G` 的對角線會是 `|w|²` 而不是 1。

3. **用未正規化的 w 當投影方向**——扣投影時如果方向向量長度不是 1，係數要除以 `|w|²`，忘了除就錯。
   先正規化再當投影方向就不會有這個問題。

4. **`w = v` 沒有複製**——之後修改 w 時連帶改到了輸入。這題每次都用 list comprehension 建新的 list，
   所以不會發生；但如果你寫成原地修改 `w[i] -= c * q[i]`，第一步一定要先 `w = list(v)`。

5. **G 和 rebuilt 寫死**——測資會過，但你沒驗證任何事。

## 延伸

- **M0.3 最小平方**：解 `A x ≈ b` 時，先做 `A = QR`，問題就變成解上三角的 `R x = Qᵀ b`，
  不用算 `AᵀA`（那會讓條件數平方，M0.6 會看到它有多糟）。`np.linalg.lstsq` 底層就是 QR 或 SVD。
- **SLAM 裡的旋轉矩陣重新正交化**：姿態估計每一步都乘一個小旋轉，浮點誤差累積幾千次之後，
  R 就不再是正交矩陣（`RᵀR ≠ I`），會開始扭曲點雲。常見修法就是定期對 R 的三個行做一次 Gram-Schmidt，
  或用 SVD 投影回最近的旋轉矩陣。
- **M0.4 特徵值**：QR 演算法——反覆做 `A = QR`、`A ← RQ`——是實務上算特徵值的標準方法。
