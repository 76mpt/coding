# 012-seconds-to-clock · 秒數轉時鐘格式 — 參考解

## 標準解

```python
def seconds_to_clock(seconds: int) -> str:
    hours, rest = divmod(seconds, 3600)
    minutes, secs = divmod(rest, 60)
    return f"{hours:02d}:{minutes:02d}:{secs:02d}"
```

O(1) 時間、O(1) 空間。三行，這就是最佳解。

## `divmod` 為什麼比 `//` 加 `%` 好

```python
hours = seconds // 3600
rest  = seconds % 3600        # 除數寫了兩次
```

同一個除數寫兩次就有兩次打錯的機會（很多人第二行打成 `% 360`）。
`divmod(seconds, 3600)` 只寫一次，而且在 CPython 裡只做一次除法運算，稍微快一點。

**看到「同時需要商和餘數」就用 `divmod`**，這是 pythonic 的判斷。

## `:02d` 的完整語法

f-string 的格式規格是 `{值:[填充字元][對齊][寬度][類型]}`：

```python
f"{7:02d}"      # '07'     0 填充，寬度 2，十進位整數
f"{7:>5d}"      # '    7'  右對齊，寬度 5
f"{7:<5d}"      # '7    '  左對齊
f"{3.14159:.2f}"  # '3.14'   浮點數，2 位小數
f"{255:08b}"    # '11111111'  二進位，補零到 8 位
f"{255:x}"      # 'ff'     十六進位
```

**寬度是「至少」不是「剛好」**——超過就照實顯示，不會截斷。
這正是為什麼 `100:00:00` 那筆測資不需要任何特別處理。

## 常見錯誤

1. **第二層對 `seconds` 而不是 `rest` 做** —
   `seconds_to_clock(3661)` 會算成 `minutes = 3661 // 60 = 61`，得到 `"01:61:01"`。
   這是最常見的錯，而且用 `3600` 以下的測資看不出來。
2. **手動補零** — 寫 `str(h) if h >= 10 else "0" + str(h)`。
   不算錯，但三個欄位就要寫三次，而 `:02d` 一個字就解決了。
3. **用 `%` 讓小時繞回 24** — 寫 `hours = seconds // 3600 % 24`，
   `86400` 會變成 `"00:00:00"`。規格說「不繞回」的時候就不要自作主張。
4. **用 `:2d` 而不是 `:02d`** — 少了那個 `0`，補的是**空格**不是零，
   會得到 `" 1: 1: 1"`。
5. **`round()` 或浮點除法** — `seconds / 3600` 得到 `1.0169...`，
   整數運算的地方不要引入浮點數。

## 延伸

反過來（`"01:01:01"` → 3661）是常見的搭配練習：

```python
def clock_to_seconds(text: str) -> int:
    h, m, s = (int(part) for part in text.split(":"))
    return h * 3600 + m * 60 + s
```

實務上處理時間**不要自己算**——用 `datetime.timedelta`：

```python
from datetime import timedelta
str(timedelta(seconds=3661))     # '1:01:01'
```

但它的格式不補零、超過一天會顯示成 `"1 day, 1:01:01"`，所以要固定格式時還是得自己來。
**知道標準庫有什麼，再決定要不要自己寫**，這是工程判斷的一部分（節點 4.1 會正式練）。
