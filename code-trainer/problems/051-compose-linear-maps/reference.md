# 051-compose-linear-maps · 合成變換就是矩陣相乘 — 參考解

## 標準解

```python
def compose_maps(A, B, points):
    def apply(M, p):
        """矩陣作用在一個點上：每個輸出座標 = 對應的『列』和 p 的內積。"""
        return [M[0][0] * p[0] + M[0][1] * p[1],
                M[1][0] * p[0] + M[1][1] * p[1]]

    def matmul(X, Y):
        """乘積的每一『行』，就是基向量走完 Y 再走完 X 之後落在哪裡。"""
        c1 = apply(X, apply(Y, [1.0, 0.0]))
        c2 = apply(X, apply(Y, [0.0, 1.0]))
        return [[float(c1[0]), float(c2[0])],
                [float(c1[1]), float(c2[1])]]

    C = matmul(A, B)
    seq = [[float(v) for v in apply(A, apply(B, p))] for p in points]
    com = [[float(v) for v in apply(C, p)] for p in points]
    return seq, com, C, matmul(B, A)
```

## 最佳解 / 另一種寫法

直接套課本公式，短很多：

```python
def matmul(X, Y):
    return [[sum(X[i][k] * Y[k][j] for k in range(2)) for j in range(2)]
            for i in range(2)]
```

這版推廣到 n×n 只要改 `range(2)`，實務上就是寫這個。
但它把「為什麼」藏起來了——學習階段先寫上面那版。

複雜度上兩者一樣（2×2 是常數），沒有優劣之分。

## 為什麼 `matmul` 可以用基向量算

多數人記的矩陣乘法是「第 i 列點乘第 j 行」：

```
C[i][j] = Σₖ A[i][k] · B[k][j]
```

這個公式是**結果**，不是**定義**。真正的定義只有一句：

> C 是那個唯一滿足「對所有 p，`C p = A (B p)`」的矩陣。

從定義推出公式只要一步——把標準基向量代進去：

```
C e₁ = A (B e₁)
```

而 `C e₁` 展開就是 `(C[0][0], C[1][0])`，也就是 C 的第一行。所以

> **乘積的第 j 行 = 把 e_j 先過 B、再過 A。**

程式裡就是 `apply(X, apply(Y, [1,0]))`。那條 `Σ` 公式只是把這句話寫成分量而已。

這跟 045 的和角公式是同一種事：`R(α)R(β) = R(α+β)` 之所以成立，
是因為矩陣乘法展開後剛好就是和角公式。你今天看到的是更一般的版本。

## 為什麼順序有差

矩陣乘法**不可交換**，因為變換的順序本來就有差：

- **先剪切再旋轉**：正方形先歪成平行四邊形，再整個轉 90 度
- **先旋轉再剪切**：正方形先轉 90 度，再往 x 方向歪

兩個不同的形狀。矩陣乘法只是忠實反映了這件事。

可以交換的都是特例，而且都有幾何理由：

| 情況 | 為什麼可交換 |
|---|---|
| 任何矩陣 × 單位矩陣 | 什麼都不做，插在哪都一樣 |
| 旋轉 × 等比例縮放 | 縮放對所有方向一視同仁 |
| 兩個 2D 旋轉 | 角度直接相加，加法可交換 |
| 兩個對角矩陣 | 各軸獨立縮放，互不干擾 |

**2D 旋轉可交換是特例，3D 旋轉不可交換。**
拿一本書先繞 x 轉再繞 y 轉，跟先繞 y 再繞 x，最後朝向不一樣。
這就是為什麼 SLAM 裡姿態不能相加——你在 M2.8 李群會正面處理這件事。

## 複雜度

- `matmul`：2×2 是常數時間。一般 n×n 樸素演算法 O(n³)
- 整體 O(n)，n 是點數；空間 O(n)

**第二條路徑比第一條快。** 這不只是理論——
對 100 萬個點連續做 5 個變換，先把 5 個矩陣乘成 1 個（5 次矩陣乘法），
再對每個點套一次，比對每個點做 5 次變換快 5 倍。

**圖形學和 CV 的 pipeline 全靠這件事**：內參 × 外參 × 模型變換先乘起來，
再一次套到所有頂點上。你 M2.1 寫相機模型時會再看到。

## 常見錯誤

1. **列行搞反**——寫成 `M[0][0]*x + M[1][0]*y`。
   用 `[[0,-1],[1,0]]` 作用在 `(1,0)` 上就抓得到：正確是 `(0,1)`，寫反得到 `(0,-1)`。

2. **`matmul` 忘了轉置**——用基向量算出來的是兩個**行**，
   直接 `return [c1, c2]` 等於把它們當**列**放，結果是正確答案的轉置。
   對稱矩陣測不出來，所以測資裡放了 `[[1,2],[3,4]]` 這種非對稱的。

3. **第二個回傳值直接複製第一個**——「反正它們相等」。
   那就等於什麼都沒驗證。隱藏測資會抓。

4. **最後一個算成 `matmul(A, B)`**——複製貼上沒改順序，
   結果第三、四個回傳值永遠相同，整個後半段的重點消失。

5. **回傳整數**——`[[0, -2], [2, 0]]` 在 Python 裡跟 float 版 `==` 相等，
   這題不會失敗；但養成明確轉 `float` 的習慣，之後跟 numpy 混用時型別不一致會咬人。

6. **`points` 是空串列時報錯**——list comprehension 本來就處理得了空串列，
   但如果你用「先取 `points[0]` 決定什麼」的寫法就會 IndexError。

## 延伸

這題是 M0.1 的地基，後面每一層都建在上面：

- **M0.2 子空間**：矩陣的行張成的空間就是「輸出可能落在哪」（行空間）。
  你今天已經算過行了——就是基向量的像。
- **M0.4 特徵向量**：有沒有哪個方向，變換後只被拉伸而不轉向？
- **M2.1 相機模型**：`P = K [R | t]`，投影矩陣就是內參與外參乘起來的合成變換。
- **M2.8 李群**：3D 旋轉不可交換，姿態要在流形上運算。

下一題問「同一個變換，換一組基底來看會長什麼樣」——那是座標變換，
也是「相機座標系 vs 世界座標系」的數學本體。
