# 056-pair-to-target · 湊出目標批次大小 — 參考解

## 標準解

```python
def find_pair(sizes, target):
    seen = {}                              # 值 → 第一次出現的位置
    for j, x in enumerate(sizes):
        need = target - x
        if need in seen:                   # 先查
            return (seen[need], j)
        if x not in seen:                  # 再放；只記第一次出現
            seen[x] = j
    return None
```

時間 O(n)（每個元素一次 dict 查詢加一次 dict 寫入，平均 O(1)）。空間 O(n)。

這就是 LeetCode 第 1 題 Two Sum，也是雜湊表最經典的入門題。

## 為什麼這樣是對的

**「j 最小」**：從左往右掃，對每個 j 問「前面有沒有補數」。第一次問到「有」就立刻回傳，
所以不可能存在更小的 j 也有答案（不然早就在那時回傳了）。

**「i 最小」**：dict 裡對每個值只存第一次出現的位置，所以查到的 `seen[need]`
就是所有等於 `need` 的位置中最小的那個。

**「不同位置」**：先查再放。查的時候 dict 裡只有 `0..j-1` 的元素，自己還沒放進去，
所以 `seen[need]` 一定 < j。

```python

```

排序之後用 006 的對撞指標，O(n log n) 時間、O(n) 空間（要記原本的位置）。
**比 dict 慢，而且「j 最小、i 最小」的規則會變得很難處理**——對撞指標找到的是
「某一組」答案，不是從左往右最早的那組。要處理 tie-break 得額外收集所有答案再挑，更麻煩。

什麼時候排序版比較好？**記憶體非常吃緊、或陣列本來就已經排好序**（那就是 O(n) 時間、O(1) 空間，
比 dict 省）。這是雜湊表和雙指標的典型取捨：

| | 時間 | 空間 | 需要排序 |
|---|---|---|---|
| dict | O(n) | O(n) | 否 |
| 排序 + 對撞指標 | O(n log n) | O(n) | 會打亂位置 |
| 已排序 + 對撞指標 | O(n) | O(1) | 本來就有序 |

## 雜湊表為什麼是 O(1)

`dict` 內部是一個陣列。放 key 的時候先算 `hash(key)`，對陣列長度取餘數，得到一個位置直接存進去。
查的時候同樣算一次 hash，直接跳到那個位置看。**不用掃過其他元素**，所以平均 O(1)。

「平均」兩個字很重要：兩個不同的 key 算出同一個位置叫**雜湊碰撞**，
碰撞多了會退化。Python 的 dict 設計得很好，實務上幾乎碰不到，
但這是面試常問的點，也是之後 C++ `unordered_map` 被刻意卡測資的原因——那在 S3 競賽節點會遇到。

## 常見錯誤

1. **先放再查**——`[3, 2, 4]` 配 6：掃到 3 就把自己放進去，接著查 3 查到自己，回傳 `(0, 0)`。

2. **每次都覆蓋 `seen[x] = j`**——同值出現多次時存到的是**最後一次**的位置，
   `[5, 5, 0]` 配 5 會回 `(1, 2)` 而不是 `(0, 2)`。

3. **用 list 當 `seen`，`if need in seen_list`**——邏輯對，但 `in` 在 list 上是 O(n)，
   整體又變回 O(n²)。這是 1.9 複雜度直覺那節講過的事，這裡是真的會超時。

4. **回傳 list `[i, j]` 而不是 tuple `(i, j)`**——這題的測試會把 tuple 轉成 list 比對，
   所以兩個都會過；但題目寫 tuple，養成照規格回傳的習慣。

5. **把 0 當成「找不到」**——`if seen.get(need):` 在 `seen[need] == 0` 時是假，
   位置 0 的答案會被漏掉。`[0, 7, 0]` 配 0、`[2, 7]` 配 9 都會抓到。要用 `in`。

## 延伸

「掃過去、把看過的東西存進 dict、對每個新元素查一次」這個模式，是 2.2 整個節點的骨架：

- **計數**：dict 存的是「出現幾次」（004 top-k 就是）
- **分組**：dict 存的是「這個 key 的所有成員」（018 就是）
- **前綴和 + 雜湊**：dict 存的是「某個前綴和出現過幾次」，用來找和為 k 的子陣列——
  那是這個節點最難的一題，會把 054 的滑動視窗推廣到**有負數**的情況

CV 裡最直接的應用是**特徵點匹配的候選查找**：把一張圖的特徵描述子量化成 key 存進雜湊表，
另一張圖的每個特徵直接查表，而不是兩兩比較——那叫 bag-of-words，ORB-SLAM 的迴環偵測就是靠它。
