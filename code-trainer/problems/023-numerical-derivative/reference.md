# 023-numerical-derivative · 數值微分：中央差分 — 參考解

## 標準解

```python
def numerical_derivative(f, x: float, h: float = 1e-5) -> float:
    return (f(x + h) - f(x - h)) / (2 * h)
```

一行。難的不是寫，是知道**為什麼是這一行**。

## 前向差分 vs 中央差分

用泰勒展開就一目了然：

```
f(x+h) = f(x) + h f'(x) + (h²/2) f''(x) + (h³/6) f'''(x) + O(h⁴)
f(x−h) = f(x) − h f'(x) + (h²/2) f''(x) − (h³/6) f'''(x) + O(h⁴)
```

**前向差分**（直接照抄定義）：

```
(f(x+h) − f(x)) / h = f'(x) + (h/2) f''(x) + O(h²)
                              └────────────┘
                               截斷誤差 = O(h)
```

**中央差分**（兩式相減）：

```
f(x+h) − f(x−h) = 2h f'(x) + (h³/3) f'''(x) + O(h⁵)      ← f(x) 和 h² 項抵消了

(f(x+h) − f(x−h)) / (2h) = f'(x) + (h²/6) f'''(x) + O(h⁴)
                                   └─────────────┘
                                    截斷誤差 = O(h²)
```

`h = 10⁻⁵` 時：前向差分誤差約 `10⁻⁵`，中央差分約 `10⁻¹⁰`。
**多一次函式呼叫，換來十萬倍的精度。**

對稱性讓所有**偶數階**的誤差項互相抵消——這個「對稱化以消去低階誤差」的技巧
在數值積分（中點法則）、有限元素法裡到處都是。

## h 該選多大：兩種誤差的拉鋸

| 誤差來源 | 隨 h 的變化 |
|---|---|
| **截斷誤差**（泰勒展開的高階項） | h 越小越好，`∝ h²` |
| **捨入誤差**（浮點相減的災難性抵消） | h 越小越糟，`∝ ε/h` |

當 h 太小時，`f(x+h)` 和 `f(x−h)` 幾乎相等，相減會損失大量有效位數——
這叫**災難性抵消（catastrophic cancellation）**。極端情況 `h = 1e-20` 時
兩者在浮點數裡完全相等，導數算出來是 0。

總誤差 `≈ C·h² + ε/h`，對 h 微分求最小值：

```
最佳 h ≈ (ε)^{1/3} ≈ (2.2×10⁻¹⁶)^{1/3} ≈ 6×10⁻⁶
```

這就是預設值 `1e-5` 的由來。（前向差分的最佳 h 是 `√ε ≈ 1.5×10⁻⁸`。）

實務上更穩健的是**相對步長**：

```python
h = 1e-5 * max(abs(x), 1.0)      # x 很大時 h 也放大
```

因為 `x = 10⁶` 時，`x + 1e-5` 在浮點數裡可能根本等於 `x`。

## 這個函式的真正用途：gradient check

你手推了一個複雜的解析梯度，怎麼知道有沒有推錯？**跟數值梯度比對。**

```python
def gradient_check(f, grad_f, x, tol=1e-6):
    analytic = grad_f(x)
    numeric = numerical_derivative(f, x)
    rel_err = abs(analytic - numeric) / max(abs(analytic), abs(numeric), 1e-12)
    return rel_err < tol
```

**判讀標準**（深度學習圈的經驗法則）：

| 相對誤差 | 判斷 |
|---|---|
| < 10⁻⁷ | 完全正確 |
| 10⁻⁷ ~ 10⁻⁴ | 通常沒問題，但如果有 kink（如 ReLU）要小心 |
| 10⁻⁴ ~ 10⁻² | **有問題**，回去檢查 |
| > 10⁻² | 一定錯了 |

PyTorch 有內建的版本：

```python
from torch.autograd import gradcheck
gradcheck(my_function, inputs, eps=1e-6, atol=1e-4)
```

**寫任何自訂的 `autograd.Function` 都應該先跑 gradcheck。**
這是研究 code 最重要的除錯習慣之一——
因為梯度錯了不會拋例外，只會讓 loss 降不下去，然後你會花三天懷疑是超參數。

## 常見錯誤

1. **用前向差分** — `(f(x+h) - f(x)) / h`。精度只有 O(h)，測資的容差不過。
2. **分母寫成 `h` 而不是 `2*h`** — 答案會剛好是兩倍。
3. **`/ 2 * h` 而不是 `/ (2 * h)`** — 運算子優先序：前者是 `(...)/2*h`，完全不同。
4. **h 寫死在函式裡** — 忽略參數，`h=1e-3` 那筆測資就是在抓這個。
5. **h 選太小**（例如 `1e-15`） — 災難性抵消，結果會是 0 或亂數。
   **「越精確越好」在浮點數的世界裡是錯的直覺。**

## 延伸

**複步長微分（complex-step differentiation）** 是一個漂亮的技巧，
可以完全避開災難性抵消：

```python
def complex_step_derivative(f, x, h=1e-20):
    return (f(complex(x, h))).imag / h
```

因為沒有做減法，所以 h 可以取到 `1e-20` 而不損失精度，
誤差是 O(h²) 但實際上等同於機器精度。
限制是 `f` 必須支援複數運算（純數學運算通常可以，含 `abs`、`max` 的就不行）。

而**真正的解法**是**自動微分**：不做近似，而是用鏈鎖律逐層算出精確的導數。
PyTorch/JAX 的核心就是這個。你在 M0.8 會手推它的數學，
在節點 5.9 會親手實作一個 tiny autograd。

數值微分不會被自動微分取代——它永遠是**驗證自動微分有沒有實作對**的那把尺。
