# 046-bayes-posterior · 貝氏定理與偽陽性 — 參考解

## 標準解

```python
def posterior(prior, sensitivity, specificity):
    tp = prior * sensitivity                 # 真陽性
    fp = (1 - prior) * (1 - specificity)     # 偽陽性
    total = tp + fp                          # 全部陽性 = 全機率
    if total == 0:
        raise ValueError("沒有人會驗出陽性，後驗機率無定義")
    return tp / total
```

四行，而且每一行對應表格的一列——**不需要記貝氏定理的符號形式，記那個 2×2 表格就好**：

```
            驗出陽性              驗出陰性
有病    prior × sens          prior × (1−sens)
沒病  (1−prior) × (1−spec)   (1−prior) × spec
```

「陽性的人裡有多少真的有病」= 第一欄的第一格 ÷ 第一欄的總和。

## 為什麼直覺會錯

人的直覺會把「**檢驗的準確度**」當成「**陽性的可信度**」，但那是兩個不同的條件機率：

```
P(陽性 | 有病) = 99%        ← 檢驗的性質，題目給的
P(有病 | 陽性) = 50%        ← 你真正想知道的
```

**條件反過來，答案天差地遠。** 這叫「**條件機率的方向**」，是貝氏定理存在的理由。

關鍵在**基本率（base rate）**：沒病的人有 9900 個，就算只誤判 1%，也有 99 個偽陽性——
跟 99 個真陽性一樣多。**分母的規模壓過了比率。**

## 三個特例的意義

| 輸入 | 結果 | 意義 |
|---|---|---|
| `sens=1, spec=0` | 後驗 = 先驗 | **檢驗沒有資訊量**——不管有沒有病都陽性，看到陽性學不到任何東西 |
| `sens=1, spec=1` | 後驗 = 1 | 完美檢驗 |
| `prior=0` | 後驗 = 0 | **先驗為 0 的東西，再多證據也救不回來**（貝氏的著名限制） |

第一個特別值得記：**「後驗 = 先驗」就是「這個觀測沒有資訊」的定義**。
M4.1 的互資訊（mutual information）量化的正是「觀測到 X 之後，Y 的不確定性降低多少」——
這裡降低了 0。

## 這條式子的三個名字

```
         likelihood × prior
posterior = ──────────────────
              evidence
```

| 名字 | 這題是什麼 | 意義 |
|---|---|---|
| **prior** 先驗 | 盛行率 | 看到資料之前的信念 |
| **likelihood** 概似 | 敏感度 | 「如果假設成立，觀測到這個的機率」 |
| **evidence** 證據 | 全部陽性的機率 | 正規化常數，讓機率加總為 1 |
| **posterior** 後驗 | 答案 | 看到資料之後的信念 |

**這四個詞是機器學習的通用語言**，之後每一節都會用到：

| 節點 | 出現形式 |
|---|---|
| **M0.10** MLE / MAP | MLE 只最大化 likelihood，MAP 加上 prior |
| **M0.10** 正則化 | L2 正則化 = 假設參數有高斯先驗的 MAP |
| **M5.1** ELBO | 變分推論就是「後驗算不出來，找個近似的」 |
| **M2.10** EKF | 卡爾曼濾波每一步都是「用觀測更新先驗得到後驗」 |

**M2.10 那條跟你的主方向直接相關**：SLAM 的濾波器本質就是不斷做貝氏更新——
先驗是「根據運動模型預測的位置」，likelihood 是「感測器讀到這個值的機率」，
後驗是「更新後的位置估計」。

## 為什麼 `total == 0` 用直接比較

```python
if total == 0:      # 這裡是安全的
```

浮點數通常不該用 `==` 比較，但這裡兩項都是機率的乘積，
**只有在兩項真的都是精確 0 時才會得到 0**（例如 `sens=0` 且 `spec=1`）。
不是那種「算到接近 0」的情況，所以直接比較是對的。

（這跟你在 029 判斷零向量、020 判斷 `value == 0` 是同一類：
**當「剛好是 0」有明確語意時，就該用 `==`。**）

## 常見錯誤

1. **分母漏掉偽陽性** —— 寫成 `tp / sensitivity` 或 `tp / prior`。這是最常見的，因為貝氏定理的分母 `P(B)` 看起來像個獨立的量，其實要用全機率展開。
2. **偽陽性寫成 `(1-prior) * specificity`** —— 少了那個 `1 −`。特異度是「沒病驗出**陰性**」的機率，偽陽性要用它的補數。
3. **沒擋分母為 0** —— `ZeroDivisionError` 而不是 `ValueError`。
4. **把敏感度和特異度搞混** —— 敏感度管「有病」那一列，特異度管「沒病」那一列。記法：**sen**sitivity 抓 **s**ick，**spec**ificity 排除健康的。
