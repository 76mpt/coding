# 077-merge-tracks · 合併軌跡區間與最大重疊

075 教的是「排對鍵」。這題教另一半：
**有些問題光是排序就解掉九成，難的是知道該排什麼。**

追蹤器給你一堆軌跡的存活區間 `[start, end]`（閉區間，整數幀號，`start <= end`）。
同一個物體常被切成好幾段——遮擋造成追蹤中斷、重新出現又接上一個新 ID，
所以區間會重疊。

實作 `merge_tracks(intervals)`，回傳兩個元素：

```
( merged,        ← 把有交集的區間合併後的結果，按左端點遞增排序
  max_overlap )  ← 任一幀上同時存活的軌跡數的最大值
```

**合併的條件是兩個閉區間有交集。** 這個邊界定義每次都有人搞錯，所以寫清楚：

- `[1,3]` 和 `[3,5]` **要**合併成 `[1,5]`——它們共用第 3 幀
- `[1,3]` 和 `[4,7]` **不**合併——沒有任何一幀同時屬於兩者，
  即使它們看起來「連在一起」（第 3 幀和第 4 幀中間沒有縫隙）

`max_overlap` 的定義：某一幀 `t` 的覆蓋數是 `#{i : sᵢ <= t <= eᵢ}`，
`max_overlap` 是所有 `t` 裡最大的那個。空輸入時是 0。

**範例**

```python
merge_tracks([[1, 3], [2, 6], [8, 10], [15, 18]])
# -> ( [[1, 6], [8, 10], [15, 18]], 2 )
#    第 2~3 幀上 [1,3] 和 [2,6] 同時存活 → 2

merge_tracks([[1, 4], [4, 5]])
# -> ( [[1, 5]], 2 )           第 4 幀兩個都在

merge_tracks([[1, 5], [2, 6], [3, 7]])
# -> ( [[1, 7]], 3 )           第 3~5 幀三個都在

merge_tracks([[1, 10], [2, 3], [4, 5]])
# -> ( [[1, 10]], 2 )          包含關係也算重疊

merge_tracks([])
# -> ([], 0)
```

第四個範例要注意：`[2,3]` 和 `[4,5]` 彼此沒有交集，
但它們都被 `[1,10]` 吃掉，所以合併後只剩一段。
而 `max_overlap` 仍然是 2，不是 3——沒有任何一幀同時有三條軌跡。

## 兩個問題，兩種排序

合併那一半，按**左端點**排序之後幾乎是送分的：一路往右走，能接就接。

最大重疊就不是了。按左端點排對它幫不上忙——
你需要的是把每個區間**拆成兩個事件**（它開始了、它結束了），然後排那些事件。
拆法和比較方式自己想，但有一個陷阱先警告你：

> 同一個座標上，「開始」和「結束」誰先處理，會改變答案。

閉區間在端點上是**同時存在**的（第二個範例的第 4 幀有兩條軌跡）。
想清楚哪一種順序才對得上這個定義——弄反的話，
`[[1,4],[4,5]]` 會算出 1 而不是 2。

**限制**
- `0 <= n <= 2 * 10^5`
- `-10^9 <= start <= end <= 10^9`，可能有完全相同的區間
- `merged` 必須按左端點遞增排序，裡面的區間互不相交
- 不要改動輸入的 `intervals`
- 大測資有時間上限。兩兩比對是 `O(n²) = 4×10^10`，必然超時
