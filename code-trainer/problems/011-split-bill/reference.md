# 011-split-bill · 分帳與無條件進位 — 參考解

## 標準解

```python
def split_bill(total: int, people: int, tip_percent: int) -> tuple[int, int]:
    with_tip = round(total * (1 + tip_percent / 100))
    per = -(-with_tip // people)          # 無條件進位
    return per, per * people - with_tip
```

O(1) 時間、O(1) 空間。這已經是最佳解。

## `-(-a // b)` 為什麼是無條件進位

關鍵在 Python 的 `//` 是 **floor division（往負無窮捨去）**，
而不是像 C/C++ 那樣往零截斷：

| 式子 | Python | C++ |
|---|---|---|
| `7 // 2` | 3 | 3 |
| `-7 // 2` | **−4** | **−3** |

所以：

```
-(-1100 // 3)
= -(-366.67 往下捨去)
= -(-367)
= 367          ← 正是 366.67 的進位
```

「取負 → 往下捨去 → 再取負」等價於「往上捨去」。這是一個值得記住的慣用寫法。

## 另一種寫法：`(a + b - 1) // b`

```python
per = (with_tip + people - 1) // people
```

原理：先加上 `b − 1`，讓「有任何餘數」的情況都被推過下一個整數界線。

- `1100 + 2 = 1102`，`1102 // 3 = 367` ✓
- `1000 + 3 = 1003`，`1003 // 4 = 250` ✓（整除時剛好不會多進一位）

兩種寫法都對，速度一樣。`-(-a // b)` 比較短，`(a + b - 1) // b` 比較好一眼看懂。
**C++ 只能用後者**（因為 C++ 的 `/` 是往零截斷，`-(-a / b)` 不成立），
所以競賽圈的習慣是後者。

## 為什麼不用 `math.ceil(a / b)`

```python
import math
per = math.ceil(with_tip / people)     # 這題會過，但有隱患
```

`a / b` 是**浮點除法**。當 a 很大時（超過 2⁵³ ≈ 9×10¹⁵），
浮點數無法精確表示整數，`ceil` 的結果可能差 1：

```python
a = 10**17 + 1
math.ceil(a / 1)      # 100000000000000000  ← 錯了，應該是 ...001
-(-a // 1)            # 100000000000000001  ← 正確
```

**只要能用整數運算得到答案，就不要繞道浮點數。** 這在金額、計數、索引上尤其重要。

## 複雜度

O(1) 時間、O(1) 空間。

## 常見錯誤

1. **直接用 `//`** — `1100 // 3 = 366`，每人少付 1 元，餐廳少收 2 元。
   規格說「不能少收」的時候，就是在講進位。
2. **整除時多進一位** — 有人寫 `with_tip // people + 1`，
   `split_bill(1000, 4, 0)` 會得到 251 而不是 250。
   測資裡那筆整除的案例就是在抓這個。
3. **回傳 float** — `with_tip / people` 得到 `366.666...`，
   或忘記 `round()` 讓 `with_tip` 變成 `1100.0000000000002`。
   規格說「必須是 int」時，型別也是規格的一部分。
4. **先四捨五入每人金額再乘回去** — 順序錯了。
   規格是「先算總額 → 再分」，不是「先分 → 再湊」。
5. **用 `math.ceil` 配浮點除法** — 這題過，但在大數字上會錯，見上。

## 延伸

「無條件進位除法」在程式裡出現得非常頻繁，記住這個慣用寫法：

- **分頁**：`總筆數 / 每頁筆數` 要進位才知道有幾頁
- **分批處理**：`資料量 / batch_size` 要進位才知道跑幾個 batch
- **卷積輸出尺寸**：`(H + 2p - k) / s + 1` 有些框架的 padding 模式要進位
- **記憶體對齊**：`(size + align - 1) // align * align`

你在節點 5.5 手寫卷積時會再遇到一次，那裡輸出尺寸算錯 1 是最常見的 bug。
