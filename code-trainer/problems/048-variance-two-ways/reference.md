# 048-variance-two-ways · 變異數的兩種公式 — 參考解

## 標準解

```python
def variance_two_ways(xs):
    n = len(xs)
    if n == 0:
        raise ValueError("空的資料沒有變異數")
    m = sum(xs) / n
    v1 = sum((x - m) ** 2 for x in xs) / n      # 定義式
    v2 = sum(x * x for x in xs) / n - m * m     # 展開式
    return v1, v2
```

## 兩條公式為什麼數學上相等

```
E[(X − μ)²] = E[X² − 2μX + μ²]
            = E[X²] − 2μE[X] + μ²          ← 期望值是線性的，可以拆開
            = E[X²] − 2μ·μ + μ²            ← E[X] 就是 μ
            = E[X²] − μ²
```

關鍵是**期望值的線性**：`E[aX + bY] = aE[X] + bE[Y]`。
這條性質讓你可以把括號展開、把常數提出來——**它是機率推導最常用的工具**。

（注意 `E[X²] ≠ (E[X])²`。那個不等式就是變異數大於 0 的原因，
也是 **Jensen 不等式**的一個特例——M0.11 會正式講。）

## 為什麼展開式在浮點下會爛掉

用 `[1e8, 1e8+1, 1e8+2]` 追一遍：

```
μ  = 100000001.0
E[X²]  = 1.0000000200000002e+16
μ²     = 1.0000000200000000e+16
         ↑ 前 16 位完全相同
相減 →   2.0        ← 只剩下最後一位，而那一位是捨入誤差
```

float64 有 **53 個二進位有效位數**（約 15–17 個十進位位）。
兩個數在前 16 位都相同時，相減的結果**幾乎全是雜訊**。

這叫**災難性抵消**（catastrophic cancellation）。
注意「災難」不在於減法本身出錯——減法算得很精確；
**災難在於誤差原本藏在低位，相減之後被放大成了整個結果**。

定義式先減掉 μ：處理的是 `-1, 0, 1` 這種數字，相對誤差從頭到尾都很小。

選哪一條，取決於中間值的量級。這就是 **M1.9「浮點誤差與病態問題」**整節的主題。

## 那展開式有什麼用

它只要**掃一遍**（同時累加 `Σx` 和 `Σx²`），定義式要**掃兩遍**（先算平均，再算平方和）。

所以在**串流資料**（資料太大放不進記憶體、或一次只來一筆）的情境下，
展開式是唯一能用的——你沒辦法「先看完全部再回頭算」。

**實務的解法是 Welford 演算法**：單遍、而且數值穩定。

```python
def welford(xs):
    n = 0
    mean = 0.0
    m2 = 0.0
    for x in xs:
        n += 1
        delta = x - mean
        mean += delta / n            # 逐步更新平均
        m2 += delta * (x - mean)     # 用「更新前」和「更新後」的差
    return m2 / n
```

它對 `[1e8, 1e8+1, 1e8+2]` 給出正確的 0.6667。
**單遍 + 穩定，兩個都要**——這就是為什麼 NumPy、pandas 內部用的是這類演算法
而不是課本上的展開式。

（`m2 += delta * (x - mean)` 那行很精巧：兩個因子分別是「更新前的偏差」和「更新後的偏差」，
乘積剛好累積出正確的平方和。想通它值得花十分鐘。）

## 母體變異數 vs 樣本變異數

```
除以 n      母體變異數 (population)   —— 這題用的
除以 n−1    樣本變異數 (sample)      —— 無偏估計
```

差別在**你是在描述手上這批資料，還是在估計背後的分布**。
用樣本平均當 μ 會讓平方和系統性偏小，除以 `n−1` 剛好補回來（貝索校正）。

`numpy.var` 預設是 `ddof=0`（除以 n），`pandas.Series.var` 預設是 `ddof=1`（除以 n−1）。
**兩個函式庫預設不同**——這是實務上很常見的困惑來源，用之前確認一下。

## 常見錯誤

1. **兩個回傳值其實是同一個** —— `v = ...; return v, v`。隱藏測資用 `got[0] != got[1]` 抓。
2. **展開式寫成 `sum(x*x)/n - m` 或 `(sum(x*x) - m*m)/n`** —— 括號錯位。正確是 `sum(x*x)/n - m*m`。
3. **除以 n−1** —— 這題要母體變異數。而且 `n=1` 時會除以 0。
4. **空 list 沒擋** —— `sum([])/0` 是 `ZeroDivisionError`，題目要 `ValueError`。
5. **建中間 list** —— `sum([(x-m)**2 for x in xs])` 多兩個中括號，10⁵ 個元素多配置幾 MB。用 genexp。
6. **以為展開式「錯了」所以要修正它** —— 這題就是要它錯。**看到差異才是重點。**

## 延伸

變異數在後面無所不在：

| 節點 | 用途 |
|---|---|
| **M0.12** 多變數高斯 | 共變異矩陣就是變異數的多維推廣 |
| **M3.4** 偏差-變異數分解 | 泛化誤差 = 偏差² + 變異數 + 雜訊 |
| **M4.4** 維度崩塌 | 用共變異矩陣的秩判斷表徵有沒有塌掉 |
| **5.10** BatchNorm | 每個 batch 算 mean/var 做正規化——**而且用的正是 Welford 的變體** |

**BatchNorm 那條跟這題直接相關**：PyTorch 的 `running_var` 用移動平均更新，
就是為了避開單次 batch 估計的不穩定。如果它用課本上的展開式，
在特徵值很大的層就會算出負的變異數（然後 `sqrt` 拋 nan）——**那是真的會發生的 bug**。
