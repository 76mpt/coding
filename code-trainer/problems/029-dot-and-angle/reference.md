# 029-dot-and-angle · 內積的兩種算法 — 參考解

## 標準解

```python
import math


def dot_and_angle(a: list[float], b: list[float]) -> tuple[float, float]:
    if len(a) != len(b):
        raise ValueError("兩個向量的維度必須相同")

    d = sum(x * y for x, y in zip(a, b))          # 座標式內積
    na = math.sqrt(sum(x * x for x in a))         # |a| = √(a·a)
    nb = math.sqrt(sum(x * x for x in b))

    if na == 0 or nb == 0:
        raise ValueError("零向量沒有方向，夾角無定義")

    cos = max(-1.0, min(1.0, d / (na * nb)))      # 夾回 arccos 的定義域
    return float(d), math.acos(cos)
```

`zip(a, b)` 把兩個序列的對應位置配成一對，走到短的那個結束為止。
**注意 `zip` 不會抱怨長度不同**——它會安靜地截斷，所以長度檢查一定要自己寫在前面，否則 `[1,2]` 和 `[1,2,3]` 會算出「內積 5」而不是報錯。
（Python 3.10 起 `zip(a, b, strict=True)` 會在長度不同時拋 `ValueError`，也是一個選擇。）

## 為什麼兩種定義相等

這是這題背後真正的數學，值得推一次。用**餘弦定理**：

```
|a − b|² = |a|² + |b|² − 2|a||b| cos θ          ← 餘弦定理，θ 是 a 與 b 的夾角
```

左邊直接用座標展開：

```
|a − b|² = Σ(aᵢ − bᵢ)² = Σaᵢ² − 2Σaᵢbᵢ + Σbᵢ² = |a|² − 2Σaᵢbᵢ + |b|²
```

兩式相減，`|a|²` 和 `|b|²` 消掉，剩下：

```
−2 Σaᵢbᵢ = −2|a||b| cos θ    ⟹    Σaᵢbᵢ = |a||b| cos θ
```

**座標式和幾何式是同一件事**，餘弦定理就是它們之間的橋。

這也解釋了為什麼「內積 = 0 ⟺ 垂直」：`cos 90° = 0`。你在程式裡看到 `[1,0]·[0,1] = 0` 得到 π/2，就是這條等式在運作。

## 那個夾住（clamp）為什麼非做不可

數學上**柯西–施瓦茲不等式**保證 `|a·b| ≤ |a||b|`，所以商一定在 `[-1, 1]`。但程式裡：

```python
a = [1.1, 2.2, 3.3]
d  = 16.939999999999998        # 分子，捨入一次
na = 4.115823125451335         # sqrt 又捨入一次
nb = 4.115823125451335
d / (na * nb) = 1.0000000000000002    # 分母比真值小了一點點
```

分子分母各自捨入之後，商可能落在數學不允許的地方。我實測過：**隨機取三維向量跟自己算，約 25% 會超出 1**。

`math.acos` 對定義域外的輸入直接拋 `ValueError: math domain error`——**不是回傳 nan，是當場中斷**。所以這不是「精度差一點」的問題，是「程式會掛掉」的問題。

```python
cos = max(-1.0, min(1.0, cos))
```

`min(1.0, cos)` 擋住上限，`max(-1.0, ...)` 擋住下限。這個「把值限制在合法區間」的動作叫 **clamp**，在數值程式裡到處都是。

**這是「數學上不可能發生的事，在浮點世界會發生」的標準例子**，也是 M1.9「浮點誤差與病態問題」整節的主題。你在 021-log-sum-exp 遇過同一類問題（`-inf − (-inf) = nan`），在 023 遇過另一類（h 太小時災難性抵消）。

## 複雜度

時間 **O(n)**、空間 **O(1)**（用 generator expression，不會產生中間 list）。這是最佳解——你至少要看過每個分量一次。

用 `sum([x*y for ...])`（多兩個中括號）會多配置一個 n 個元素的 list，10 萬維時是幾 MB 的浪費。這個差別你在 021 的 review 裡看過實測。

## 常見錯誤

1. **沒 clamp** —— 小測資全過，`[1.1, 2.2, 3.3]` 那筆直接 `ValueError: math domain error`。這是最容易漏的一個，因為「向量跟自己夾角為 0」感覺是最單純的情況。
2. **忘記檢查長度** —— `zip` 會安靜截斷，於是 `[1,2]` 和 `[1,2,3]` 算出內積 5、完全不報錯。**安靜給出錯答案比當掉更糟。**
3. **零向量沒擋** —— 除以 0 會拋 `ZeroDivisionError`（float 的話是 `nan`），而題目要的是 `ValueError`。錯誤類型也是規格的一部分。
4. **回傳角度而不是弧度** —— `math.acos` 給的是弧度。要度數得再乘 `180/π`，這題不用。
5. **用 `math.dist` 或自己算 |a−b| 再套餘弦定理** —— 會過，但繞了一大圈，而且多一次減法就多一次捨入。
6. **`na == 0` 用近似比較（如 `abs(na) < 1e-12`）** —— 這裡反而**不該**近似。只有真正的零向量才會讓 `sqrt(Σx²)` 得到剛好 0.0；用容差反而會把「非常短但合法」的向量誤判成零向量。
