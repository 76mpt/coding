# 044-rotate-points · 手寫旋轉矩陣 — 參考解

## 標準解

```python
import math


def rotate_points(points, theta):
    c = math.cos(theta)
    s = math.sin(theta)
    return [(c * x - s * y, s * x + c * y) for x, y in points]
```

三行。`cos`/`sin` 算一次、comprehension 一次走完。

## 為什麼矩陣長那樣

矩陣的**每一行就是基底向量變換後的落點**——你在 035-det-and-area 學過這句話。

```
(1, 0)  轉 θ 之後  →  (cos θ, sin θ)      ← 第一行
(0, 1)  轉 θ 之後  →  (−sin θ, cos θ)     ← 第二行
```

第一個是單位圓上角度 θ 的點，這是 `cos`/`sin` 的定義。
第二個是它再轉 90 度（`(x,y)` 轉 90 度變成 `(−y, x)`）。

**所以旋轉矩陣不用背——畫一個單位圓，把兩個基底向量轉過去，讀出座標就是了。**

## 「長度不變」為什麼能驗證正確性

```
|R p|² = (cx − sy)² + (sx + cy)²
       = c²x² − 2csxy + s²y² + s²x² + 2csxy + c²y²
       = (c² + s²)x² + (c² + s²)y²
       = x² + y²                    ← 用了 sin²θ + cos²θ = 1
```

中間的 `2csxy` 項**剛好抵消**——那是因為第一行的減號和第二行的加號。
**符號寫反的話交叉項不會消，長度就會隨角度變動。**

所以「長度不變」不只是個好性質，它是**你的符號有沒有寫對的檢驗**。
這跟 030 用「殘差正交」驗證投影是同一種手法：**用一個獨立的數學事實檢查實作**。

## 保長度的矩陣叫正交矩陣

```
RᵀR = I        而且        det(R) = +1
```

滿足第一條的叫**正交矩陣**（保長度、保角度）；
再加上第二條（行列式為 +1）才是**旋轉**——`det = −1` 的是鏡射，它也保長度但會翻面。

**這個區分在 M2.7 旋轉表示是致命的**：
從資料估出來的 3×3 矩陣如果 `det = −1`，你把它當旋轉用，整條軌跡會鏡像翻轉，
而且過程中沒有任何錯誤訊息。**檢查 `det(R) = +1` 是必要步驟。**

（035 那題你算過 `[[0,1],[1,0]]` 的 `det = −1`——那就是一個鏡射。）

## `c, s` 要提到迴圈外

```python
[(math.cos(theta)*x - math.sin(theta)*y, ...) for x, y in points]   # 每個點呼叫 4 次
c, s = math.cos(theta), math.sin(theta)                            # 總共 2 次
```

10 萬個點的話是 **40 萬次 vs 2 次**三角函數呼叫。
`theta` 在迴圈裡從來不變，所以那是純粹的浪費——**常數提出迴圈**，跟 043 講的是同一件事。

## 複雜度

時間 **O(n)**，空間 O(n)（要回傳 n 個新點）。這是最佳解。

NumPy 版本會是 `points @ R.T`，一次算完所有點——**5.4 影像幾何變換**那節會讓你改寫成那樣。

## 常見錯誤

1. **符號寫反** —— `x·cosθ + y·sinθ` 會變成順時針。測資 `(0,1)` 轉 90 度專門抓（正確是 `(-1,0)`，寫反會得到 `(1,0)`）。
2. **用角度而不是弧度** —— `math.cos(90)` 不是 0，是 `-0.448`。要轉的話用 `math.radians(90)`。
3. **`cos`/`sin` 寫在 comprehension 裡** —— 會過，但大測資慢很多。
4. **兩行的 x、y 用錯** —— 第二行是 `s*x + c*y`，很多人寫成 `s*y + c*x`。
5. **回傳整數** —— 用 `int()` 截斷會丟精度，測資用近似比較但差 0.5 還是不會過。
