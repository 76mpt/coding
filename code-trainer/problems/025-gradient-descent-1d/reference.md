# 025-gradient-descent-1d · 一維梯度下降（看見學習率的威力與災難） — 參考解

## 標準解

```python
def gradient_descent_1d(df, x0: float, lr: float, steps: int) -> float:
    x = x0
    for _ in range(steps):
        x -= lr * df(x)
    return x
```

四行。**這就是所有深度學習優化器的核心**，其餘全是在這條式子上加東西。

## 學習率決定一切：對 f(x) = x² 的完整分析

`f'(x) = 2x`，所以更新是：

```
x ← x − lr·2x = (1 − 2·lr)·x
```

每一步就是**乘上一個常數** `r = 1 − 2·lr`。n 步之後 `xₙ = r ⁿ · x₀`。
收斂與否完全取決於 `|r|`：

| lr | r = 1−2lr | 行為 |
|---|---|---|
| 0.01 | 0.98 | 收斂，但很慢 |
| 0.1 | 0.8 | 漂亮的指數收斂 |
| **0.25** | **0.5** | 每步減半 |
| **0.5** | **0** | **一步到位**（最佳） |
| 0.9 | −0.8 | 震盪衰減（左右跳但幅度變小） |
| **1.0** | **−1** | **永遠震盪**，不收斂也不發散 |
| 1.1 | −1.2 | **發散**，`1.2⁵⁰ ≈ 9100` |

**收斂條件**：`|1 − 2·lr| < 1`，也就是 `0 < lr < 1`。

一般地，對 `f(x) = ½ a x²`（二階導數是 a），收斂條件是 `lr < 2/a`，
最佳學習率是 `lr = 1/a`。

**這推廣到多維就是**：`lr < 2/L`，其中 L 是 Hessian 的最大特徵值（Lipschitz 常數）。
你在 M1.2 會正式學這個。

## 為什麼有些函數收斂得特別慢

看隱藏測資 `f(x) = x⁴`（`f'(x) = 4x³`），從 x=2 跑 500 步只到 0.157。

原因是**梯度隨著接近最小值而快速趨近 0**：x=0.157 時梯度只有 `4×0.157³ ≈ 0.015`，
每步只前進 0.00015。**越接近目標走得越慢。**

這在深度學習裡就是**平坦區域（plateau）**問題。對應的解法：

- **momentum** — 累積過去的方向，在平坦區保持速度
- **Adam / RMSProp** — 用梯度的歷史大小做正規化，梯度小的時候自動放大步伐
- **learning rate warmup / schedule** — 動態調整 lr

反過來，`lr` 太大在**狹長山谷**（Hessian 條件數大）的地形上會沿著陡峭方向震盪、
沿著平緩方向幾乎不動。這就是**條件數**對最佳化的影響——M0.6 和 M1.2 的主題。

## 從這裡到 Adam

```python
# 原味 SGD
x -= lr * grad

# + momentum：累積速度，衝過小坑和平坦區
v = beta * v + grad
x -= lr * v

# + Adam：再除以梯度大小的移動平均，讓每個方向的有效步長自適應
m = b1 * m + (1 - b1) * grad              # 一階動量（方向）
s = b2 * s + (1 - b2) * grad**2           # 二階動量（大小）
x -= lr * m_hat / (sqrt(s_hat) + eps)     # m_hat/s_hat 是偏差修正後的值
```

**每一行都還是同一個骨架**：算梯度 → 決定步伐 → 更新。
你已經寫出最核心的那一步了。

## 常見錯誤

1. **用 `+` 而不是 `−`** — 那是梯度**上升**。`x²` 會直接發散。
   記法：**梯度指向上坡，最小化要往下坡走，所以是減。**
2. **在迴圈裡只算一次 `df(x)`** — 每一步都要用**當前** x 的梯度重新計算。
   若把 `g = df(x0)` 提到迴圈外，就變成固定步長的直線移動了。
3. **試圖提前停止** — 加了「梯度很小就 break」的判斷。
   規格說跑滿 `steps` 次，測資會抓到差異（尤其是震盪的 `lr=1.0` 那筆）。
4. **`steps=0` 特別處理** — 不需要，`range(0)` 本來就是空的。
5. **回傳 `x0`** — 如果你寫 `x0 -= lr * df(x0)` 然後 `return x`，那個 `x` 根本沒定義。

## 延伸：這條式子在你的主方向裡

SLAM 的**位姿最佳化**本質上就是這個迴圈，只是：

- `x` 從純量變成 **SE(3) 上的位姿**（不能直接做減法！）
- 更新變成 `T ← exp(−lr · ξ) · T`，其中 `ξ` 是李代數上的梯度
- 實務上用 Gauss-Newton / LM 而不是純梯度下降（收斂快得多）

**「不能直接做減法」正是為什麼要學李群李代數**（M2.8）——
旋轉矩陣減去一個旋轉矩陣不是旋轉矩陣，所以梯度下降的第一步就卡住了。
李代數提供了一個可以做加減法的空間，讓這條式子重新可用。

M1.4 的 Gauss-Newton / LM 會告訴你為什麼實務上不用純梯度下降：
它利用了「殘差平方和」這個特殊結構，用 Jacobian 近似 Hessian，收斂快好幾個數量級。
