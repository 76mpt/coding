# 055-sync-sensor-streams · 相機與 IMU 的時間對齊 — 參考解

## 標準解

```python
def nearest_imu(cam, imu):
    result = []
    j = 0                                   # IMU 指標，整個過程只往右走
    for t in cam:
        # 右邊那筆「嚴格更近」才前進；同距離不動 → 自動取較小索引
        while j + 1 < len(imu) and abs(imu[j + 1] - t) < abs(imu[j] - t):
            j += 1
        result.append(j)
    return result
```

時間 O(n + m)：for 迴圈走 n 次，`j` 全程最多前進 m − 1 次。空間 O(n)（輸出）。

這已經是最佳解——每筆 cam 至少要輸出一個答案，每筆 imu 最壞情況也得看過，O(n + m) 是下界。

## 為什麼 `j` 不用回頭（正確性論證）

兩個事實：

1. **固定 t 時，距離 `|imu[k] − t|` 對 k 是 V 形**（先嚴格遞減、後遞增）。因為 imu 嚴格遞增，
   在 t 左邊的點越往右越近，在 t 右邊的點越往右越遠。所以從任何左側位置往右走，
   「右邊一筆沒有更近就停」一定停在谷底——也就是最近點（同距離時停在左邊那個）。

2. **t 變大時，谷底不會往左移。** 設 `cam[i]` 的答案是 j。對 `k < j`，
   有 `|imu[j] − cam[i]| <= |imu[k] − cam[i]|`，而 `imu[j] > imu[k]`。
   t 往右移只會讓離 t 更遠的左邊點 `imu[k]` 更遠（相對於 `imu[j]`）。
   所以 `cam[i+1]` 的答案 >= j，指標從 j 繼續往右找就對了。

這兩點合起來，就是「兩個排序陣列、兩個指標、都不回頭」的標準論證。

## 另一種寫法：對每張影像二分搜尋

```python
import bisect

def nearest_imu(cam, imu):
    result = []
    for t in cam:
        k = bisect.bisect_left(imu, t)      # 第一個 >= t 的位置
        if k == 0:
            result.append(0)
        elif k == len(imu):
            result.append(len(imu) - 1)
        elif t - imu[k - 1] <= imu[k] - t:  # 左邊不比右邊遠 → 取左（較小索引）
            result.append(k - 1)
        else:
            result.append(k)
    return result
```

O(n log m)，比雙指標慢一個 log，但**不需要 cam 有序**。實務上兩種都常用：

- cam 一批一批來且有序 → 雙指標，而且可以做成串流（每來一張只推 j，不用存整個陣列）
- 隨機查詢任意時間點 → 二分搜尋

這題的 2×10^5 規模兩者都過得了。重點是你要知道**排序帶來了什麼**：
它讓暴力解的「每次從頭找」變成不必要。

## 常見錯誤

1. **`j = 0` 寫在 for 迴圈裡面**——每張影像都從頭找，退化成 O(n·m)。
   功能正確、小測資全過，只有大測資超時。這是這題最常見的錯。

2. **用 `<=` 判斷要不要前進**——同距離時會跑到較大索引。
   `nearest_imu([12], [8, 16])` 會回 `[1]` 而不是 `[0]`。

3. **越界**——寫成 `while abs(imu[j+1] - t) < ...` 忘了先檢查 `j + 1 < len(imu)`。
   影像時間晚於所有 IMU 時會 IndexError。`[100, 200, 300]` 配 `[0, 10, 20, 30]` 會抓到。

4. **只找「第一個 >= t 的 IMU」**——那是「下一筆」不是「最近的一筆」，
   忘了比較左邊那筆。`cam=[10]`、`imu=[8, 16]` 會回 1，正確是 0。

5. **二分寫法同距離取錯邊**——`t - imu[k-1] < imu[k] - t` 用了嚴格小於，
   同距離會取右邊。這題要 `<=`。

## 延伸

這就是真實 VIO 系統（VINS-Mono、ORB-SLAM3、OpenVINS）在每張影像進來時做的第一件事。
實務上會再往前走兩步：

- **不是取最近一筆，而是取兩筆做線性插值**，得到剛好在影像時間點的 IMU 讀數
- **取兩張影像之間所有的 IMU 讀數做預積分（preintegration）**——
  那會在 M2 的 SLAM 節點出現，資料對齊的邏輯就是這題

雙指標四種形態你都練過了：

| 形態 | 例子 |

| 對撞指標（同一陣列，兩端往中間） | 006 |
| 快慢指標（同一陣列，同向不同速） | 053 |
| 滑動視窗（同一陣列，同向夾區間） | 054 |
| 雙序列指標（兩個陣列各一個指標） | 這題 |
