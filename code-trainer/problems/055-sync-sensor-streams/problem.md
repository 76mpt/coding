# 055-sync-sensor-streams · 相機與 IMU 的時間對齊

- 階段：資料結構與演算法（LeetCode 風格） / 2.1 陣列與雙指標
- 語言：Python　難度：standard　互動方式：實作函式
- 要實作的入口：`nearest_imu`
- 提示：共 4 階（`python trainer.py hint 055-sync-sensor-streams`）
- 測資：10 筆（`python trainer.py test 055-sync-sensor-streams`）

────────────────────────────────────────────────────────────────────

視覺慣性 SLAM（VIO）同時讀相機和 IMU。兩個感測器各跑各的時鐘，
相機一秒 30 張、IMU 一秒 200 筆，時間戳對不齊。
處理每一張影像之前，第一件事是找出**時間上最接近它的那筆 IMU 資料**。

給兩個**已經由小到大排好**的時間戳陣列 `cam` 和 `imu`（單位：毫秒），
對 `cam` 裡的每一個時間戳，找出 `imu` 裡跟它**距離最近**的那一筆的**索引**。
如果兩筆一樣近，取**索引比較小**的那筆（比較早的）。

實作 `nearest_imu(cam, imu)`，回傳一個 list，長度跟 `cam` 一樣，
第 i 個元素是 `cam[i]` 對應到的 `imu` 索引。

**範例**

```
nearest_imu([10, 25, 40], [0, 8, 16, 24, 32, 40])  ->  [1, 3, 5]
```

- `cam[0] = 10`：最近的是 8（距離 2），索引 1
- `cam[1] = 25`：最近的是 24（距離 1），索引 3
- `cam[2] = 40`：剛好等於 40，索引 5

```
nearest_imu([12], [8, 16])          ->  [0]      # 距離都是 4，取索引小的
nearest_imu([-5, 100], [0, 50])     ->  [0, 1]   # 超出兩端就取最靠邊的那筆
nearest_imu([], [1, 2, 3])          ->  []
```

**限制**
- `0 <= len(cam) <= 2 * 10^5`，`1 <= len(imu) <= 2 * 10^5`
- `cam` 非遞減（可能有重複），`imu` **嚴格遞增**
- 時間戳是整數，`-10^9 <= 值 <= 10^9`

**效能要求**：測資裡有一筆兩邊各 200,000 筆的大測資與時間上限。
對每張影像都掃一遍整個 IMU 陣列是 O(n·m) ≈ 4×10^10 次運算，必然超時。

兩個陣列**都已經排好序**——這個條件是關鍵。想一想：
處理完 `cam[i]` 之後，處理 `cam[i+1]` 的時候，IMU 那邊需要從頭找起嗎？
